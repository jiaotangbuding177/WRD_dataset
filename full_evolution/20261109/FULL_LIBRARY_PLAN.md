# 用 14B 小模型维护 WRD 技能库

> **2026-11-12 执行状态。** 1,107 条档案可恢复。当前 Git 入口可做分阶段案例对照，批量归并、独立试用与正式入库的全量接线待完成。先阅读 [H 批审计和可运行交接](FULL_LIBRARY_READINESS.md)。

## 交付目标

从历史企业会话里找出可以重复使用的工作方法，把它们做成可执行、经试用的技能，按任务类型维护一个版本化技能库。**14B-241 负责筛选、制作、试用、修订和审核。** 每个阶段由固定的原生 OpenClaw 执行。管道准备材料、传递实际文件、记账，并按验收结果更新技能库。

输入是完整会话、实际可用附件、工具结果、用户的后续纠正和当前技能目录。全量建库对照使用归档中的全部 1,107 条来源。原 881／226 来源标签保留。使用现有 241 检查点时，按有已知训练来源重合的历史工作量重放报告。纳入该轮建库的来源及关联材料需与独立业务验收分开，原 226 仍与训练及门槛调整隔离。已有正式 29 项可作为日常维护起点，继续登记原作者与版本。从空库建设和从既有库扩展分开报告，各模型比较使用同一初始快照。

## 一条路线怎么进入技能库

| 环节 | 14B-241 做什么 | 交付与接续 |
| --- | --- | --- |
| **1. 筛选与归并** | 按批读相近会话和现有路线卡。检查工作目标、输入、关键步骤、交付物和适用条件，保留晚于初始委托的纠正。指出实际能替代的规划、代码、处理或操作工作 | 交路线卡和每份会话的去向。可复用、合并补证、更新旧技能、新建、暂缓或无复用价值。跨批对同一路线去重后才排制作 |
| **2. 制作与自测** | 读取该路线的完整来源和材料，做出短首页及必要的程序、模板或资料。执行公开用法，检查正常输入和相关边界。真实报错时修对应文件并重跑 | 交实际 `SKILL.md`、配套资源、命令、输入、退出状态和结果。试跑记录放在包外。关键依赖不齐时交缺口，候选仍可保全 |
| **3. 用新任务成对试用** | 从与制作来源分开的真实开发请求中，选主工作匹配、材料齐备的任务。沿用原入口，每条路线最多选两项，只有一项符合条件就用一项，零项则写明缺口。每个任务用同一 14B-241 开两个独立原生会话，一组直接执行，一组可发现候选技能。原始委托、附件、工具和预算一致 | 交两组真实业务产物、工具轨迹、实际技能发现和读取证据、资源使用、tokens 及调用数。制作自测通过后才进入试用。业务执行只收到冻结委托和材料，历史答案及验收答案留在审核侧 |
| **4. 审核并定向修订** | 审核会话读取实际交付物、版本和成对账本，判断技能是否真的替代了工作。若发现可定位的缺陷，把失败命令、工具返回、问题位置和原包交回修订会话 | 每个候选版本先允许一次局部修订。修复必须写进实际包，按公开命令重跑，并用修订版重验所有要求的成对开发任务。改错工作路线回到筛选；缺材料暂缓；确无复用价值则淘汰 |
| **5. 入库或保留现状** | 14B-241 给出保留、修订、暂缓或淘汰的建议并引用证据。管道按相同规则检查真实文件、版本、试用及用量是否齐全 | 满足下方保留条件才发布。新增路线建立正式技能，更新路线沿用原技能 ID 并增加版本。未获选的候选和旧版本仍可追溯 |

### 筛选要补足什么信息

每批给出相关完整会话的位置、原件和已恢复附件的区别、用户哪一轮纠正了什么、实际做成或失败的证据，以及库中最相近的几条路线。分类和检索只缩小阅读范围。模型据完整证据判断，附件缺失须说明具体影响。某一路线虽缺历史原件，若仍能在较窄范围以明确来源的新输入验证，可以继续候选。确实无法判断或试用时标暂缓。一次会话可支持多条路线，单来源也可支持独立价值明确的小路线。

同一主流程中的企业名、日期、格式参数等变化归到同一路线。已经覆盖的来源只增加血缘记录。共享一个程序但主要交付不同，可复用程序并各自保留路线。跨批使用稳定的路线 ID 和当前目录版本，同一轮同一路线只安排一次新建或更新。比如两段会话都是比较两轮作业，按稳定 ID 比对和区分缺交可合并为一个技能；另一个会话如果只分析单人的长期学习变化，由筛选判断是否属于现有技能的分支。

### 审核要过哪些条件

沿用 WRD 的正式保留条件。资源能按首页公开用法运行，技能组确实使用了工作流或资源，所有要求的成对任务都达到交付标准，并且技能组**总 tokens 和模型调用总数都严格低于无技能组**。按该候选版本要求的全部试用计算总量，允许单题增耗，阅读、适配、失败及恢复都计入。重要用量缺失时暂缓。无技能回执只有在任务、附件、执行模型、工具、预算和运行条件相同且证据完整时才能复用。

审核会话与制作会话隔离，收到的是冻结工件和真实回执。交付成功率 TSR 检查所需产物是否齐全、非空并可打开；业务质量 Q 单独按论文的正确性与依据、覆盖、需求适配、业务可用性、表达呈现评价。制作自测、技能使用成本和业务质量分别记账。修订时记录失败版本、实际变动和同输入复验。临时换命令跑通后还要核对最终技能是否写入了可复用的修复。

## 技能库平时怎么维护

- **正式库**按任务类型组织，每条路线有一个当前生效版本，包含 `SKILL.md` 及自足资源。记录来源、适用边界、上一个版本和验收回执。技能首页写清入口、参数和何时适用，制作轨迹、测试答案和评审保存在库外。
- **候选区**保留待试用、待修和待补材料的版本。原版本继续服务。新版本过完整验收后，以整包为单位切换正式指针，旧版本保留可回退，切换异常时回到已验版本。并发修改同一路线时，以同一基础版本串行验收，防止互相覆盖。
- **新增材料**优先找现有路线。仅增加来源证据时更新目录。改变适用范围、操作步骤或资源时生成新版本并复验。有证据表明两个技能重复时，验证合并版仍覆盖原边界及已通过任务，再切换目录。对任务找不到适用技能时，继续按原生方式直接执行。
- **账本**按来源组、路线和版本记录去向。总量报新增、复用、更新、暂缓、淘汰和实际在用技能数；质量报漏筛、错并、重复提案、修订解决率、合格率和业务 Q；成本报建库总开销、每合格技能的总成本、实际使用减负。失败与设施中断分别记，未知不填零。

## 如何验证小模型能接手全流程

先用既有四组做接线回归，再冻结一批未见、无训练血缘的来源组，覆盖合并、已有技能更新、新建、缺证据及真实失败后修订。**主对照让 14B-0、14B-241、GLM-5.3-Flash 各自完成全部阶段**，使用同样的初始库、材料、提示、原生工具和预算。分别比较候选路线、合格包、修订结果和建库成本。另对各臂的合格包用同一个冻结执行模型、同一批独立业务任务做无技能／有技能配对，量化质量和复用收益。正式盲评的委托和附件在路线筛选之前就隔离，只在最终业务评估交给固定执行器，验收答案留在评分侧。这样可以分开回答训练带来的增益、相对 GLM 的产出差距，以及新库能省多少执行工作。共同路线卡的制作小对照保留为定位工具。

每阶段按真实工作量独立给预算，完成后保存终态和工件。试点先确认路线和证据能正常流转，再从实际耗时和失败样本冻结生产预算。放宽额度、调整推理参数或增加复验轮次均作为新的条件记录。先做少量完整路线后扩批，正式库规模由入库结果决定。

目前 Git 的三段简化入口已实现路线、制作、复验及物理交接。本文补齐了批量归并、独立成对业务试用、审核入库和版本维护的设计。这些生产接线及全流程小模型效果仍待实施和实测，本轮只交方案。原生流程和保留条件沿用 WRD 方法稿及原生产入口，现有材料与投递链见 [历史管道与演化集](HISTORICAL_DELIVERY.md)，当前可运行的诊断入口见 [简化管道交接手册](THIN_PIPELINE.md)。
