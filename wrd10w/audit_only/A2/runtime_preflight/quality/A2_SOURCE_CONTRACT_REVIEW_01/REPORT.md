# A2终态独立语义审查

A2完整覆盖了46个来源，但当前四条输出不能直接当成四条合格公共工作流。实际共享机制最清楚的是RC2的JD＋简历匹配；RC1需拆分完整工作流，RC3只能先视为待验证的PPT构建/渲染组件，RC4是恢复清单。A2没有新业务试跑或合格技能结果，不能据七个“继续”标签宣称训练正例或足量。

原两份文件SHA与父任务给定终态一致，未改原件。A2实际11模型调用、1,134,348 tokens、960.141秒；本审查没有调用原生Agent、容器或业务模型，也没有授主集正loss。此次是新AI银标审查，未做human gold或原R全文质量审查。Codex语义审查本身的算力与现金成本未知，不记作0。

逐46画像、四路线和精确字段问题见 `SEMANTIC_REVIEW.json`。所有49段quote文字均为对应case原user子串，但三条message_id错位，只有46/49身份正确；Excel画像还把两个不同source/不同群说成同一会话。独立核查明细在 `SEMANTIC_REVIEW_QA.json`，与父任务机械审查一致。父任务已另证五份输入真实全文送达，因此这些内容问题不能归因于附件输入包未读或漏投user文本。

## 主要结论

1. **RC1过粗归并且基础计数错误。** 六案实际是1 PDF＋3 DOCX＋1 PPTX＋1 TXT；原输出写成2 PDF＋2 DOCX。PPT首页问答、全文专利条款摘录、合同风险、百回叙事分布、预算编制和公文PDF不是同一完整工作流。它们可能共享按格式提取内容的组件，但预算/排版与引文检索不能借一个消费者的结果互授业务收益。格式差异也不能未实测就说都是“一行命令”。
2. **“通用能力能做”没有回答资源能否替代重复劳动。** HTML/游戏/Excel转换有明显的构建或导出操作，A2仅保留截图/重算，并用实现成熟、规格完整、脚本一步来排除资源。两份明确的前端招聘流程也因规格不同被分开。应将这些判断保留为待证先验，检查最小代码/模板实际替代的规划、输入控制、状态循环、布局和导出工作，再由质量与总成本检验；本审查同样没有证明它们必然有用。
3. **先导反例被升成了未授权硬规则。** 两例重ledger写作增耗不能推出所有短内容都增耗，不能推导资源一律“一页/半页”，也不能在所有领域禁止必要schema或程序。原设计要求最小必要资源，而不是固定篇幅。
4. **RC2是可信候选，评测协议仍不够。** 两份JD＋真实简历文件的输入/判断机制确实对应，但A2没读简历正文，画像中的“已挂”应改成源包存在、待真实挂载。只按引用数量/正确率判胜会忽略招聘结论和缺证判断，也会错误丢掉同质量但更便宜的资源。必须先明确Maker看到哪份全文、哪份是Maker未见正文的开发消费例，随后才谈同版本独立试跑。
5. **RC3把材料结构当作环境证据。** 40页PPTX XML存在不证明原生环境已能读、构建或渲染；LibreOffice/Chromium/python-pptx可用性与真实产物还未验证。两次自然输出没抓到缺陷也不证明检查无用，原方案没有这个“两次无缺陷就降级”的规则。

## 可定位的当前任务错误

- `40bdee…`：jtml尚未确认，原画像直接改成已定HTML。
- `38e19f…`：现有消息提供了可整理的简短事实，不能笼统说正文不存在、任何执行均须先恢复；更完整纪要可单列缺口。
- `67980a…`：ROI参数并未全部给齐。60%工单自动化不是60%工资节约；现金兑现、工时和部分成本须作为显式假设。
- `0e242f…`：每人年20万换算月度值已可直接计算，缺旧整表不构成该最小任务无法执行。
- `54e027…`：预算数字齐备不表示完整技术项目计划的组织/技术事实齐备；占位草稿只是部分交付。

其余许多字段保留了正确当前意图、真实输入位置和具体unknown，尤其简历缺件、公司两材料主体歧义、图像provider未测、出题不提供方法、招聘流程不要求实际筛30份等。这些正确理解应与错误决策分开，不因输出有错全部丢弃，也不因覆盖率高或引文文字正确整包授信。
