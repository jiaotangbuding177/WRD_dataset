## 🛡️ Agent 安全（13 篇）

### 1. Agent Data Injection Attacks are Realistic Threats to AI Agents
- **链接**: https://arxiv.org/abs/2607.05120
- **一句话核心**: 提出了一种新的间接提示注入类别——Agent Data Injection (ADI)，攻击者将恶意数据伪装成可信元数据（如邮件发件人字段、URL、工具名称），而非伪装成指令，绕过现有防护。
- **为什么重要**: 现有 IPI 防御几乎都聚焦于"指令注入"，但 ADI 攻击的是 agent 对"数据锚点"的信任，现有防御体系存在系统性盲区。

### 2. DualView: Preventing Indirect Prompt Injection in Personal AI Agents
- **链接**: https://arxiv.org/abs/2607.03821
- **一句话核心**: 提出一种双 LLM 架构防御方案——AgentView 作为中介层将不可信数据"符号化"，使 agent 永远不直接处理攻击者文本，从而在架构上消除 IPI 攻击面。
- **为什么重要**: 不是"检测"而是"消除"攻击面，且能跨文件写入-读取路径追踪符号，阻断存储型 IPI 和记忆中毒的持久化路径。

### 3. Beyond the Prompt: Jailbreaking Function-Calling LLMs via Simulated Moderation Traces
- **链接**: https://arxiv.org/abs/2607.00481
- **一句话核心**: 发现通过功能调用的 moderation traces（验证消息/约束反馈）可在共享上下文中绕过安全策略，攻击面从单轮提示扩展到了工具定义、输出和验证信息。
- **为什么重要**: 现代 agent 的 function-calling 架构将信任平面与数据平面混合到同一上下文窗口，这一设计弱点带来了全新的攻防维度。

### 4. MOSAIC: Knowledge-Guided CLI Command Composition Attack in LLM Coding Agents
- **链接**: https://arxiv.org/abs/2607.02857
- **一句话核心**: 发现"单条命令无害、组合后危险"的 CLI 命令组合风险（CCR），从 CVE 中蒸馏知识构建 exploit 路径，在 Claude Code / Codex CLI 等 coding agent 上验证。
- **为什么重要**: 突破了传统 agent 安全研究的"指令层"局限——攻击信号不在单条命令或文本中，而在命令间的状态传递中，现有防御完全无力。

### 5. FORGE: Research-Trajectory Hijacking Attacks on Deep Research Agents
- **链接**: https://arxiv.org/abs/2607.04718
- **一句话核心**: 攻击者通过种子文档污染检索池，在 deep research agent 的多轮规划和合成环节中逐步劫持推理轨迹，最终控制研究报告内容。
- **为什么重要**: 揭示了 retrieval-planning 耦合带来的新攻击面——不同于标准 RAG 的一次性污染，deep research agent 的连续规划让污染「传播」到报告级。

### 6. Untrusted Content Masking for Web Agents with Security Guarantees
- **链接**: https://arxiv.org/abs/2607.05277
- **一句话核心**: 对于 web agent 而言，渲染页面天然混合了可信与不可信内容，破坏了信任边界；本文提出 Untrusted Content Masking (UCM) 从架构上消除攻击面。
- **为什么重要**: 证明了即使是 web agent 也可以实现"零暴露"防御，而非依赖启发式检测。

### 7. Securing Multi-Tool AI Agent Chains With Dynamic, Real-Time Compositional Policies
- **链接**: https://arxiv.org/abs/2607.03423
- **一句话核心**: 针对基于 MCP 的多工具 agent 链，提出实时动态策略执行机制，并报告了 MCP 生态中的跨 Server 内存泄露、隐式提示注入（95% 逃逸率）、工具投毒等漏洞。
- **为什么重要**: MCP 正成为 agent 工具调用的主流协议，这篇论文系统性地揭示了 MCP 层的安全风险。

### 8. Swarm-Driven Multi-Agent Reasoning for Smart City Security
- **链接**: https://arxiv.org/abs/2607.03628
- **一句话核心**: TPSC-Sec 框架用 5 个专用 agent 协同推理，量化了各风险源的贡献：工具误用（0.32）> 幻觉传播（0.30）> 提示注入（0.29）> 数据泄露（0.27）。
- **为什么重要**: 首次用统计学方法量化了 agent 安全中各风险因素的权重关系，为防御优先级提供数据支撑。

### 9. (A)I Sees What You Don't: Exploiting New Attack Surfaces in Third-Party Mobile Agents
- **链接**: https://arxiv.org/abs/2607.00333
- **一句话核心**: 发现移动端 agent 三类新攻击面：屏幕感知攻击（利用圆角/隐藏区注入）、通道滥用攻击（ADB 调试接口作生产用导致提权）、多租户隔离失败。
- **为什么重要**: 移动 agent 架构正在快速增长，但 OS 级安全边界在设计时未被 agent 框架考虑，这是一个系统性风险。

### 10. Safety Testing LLM Agents at Scale: From Risk Discovery to Trajectory-Level Evaluation
- **链接**: https://arxiv.org/abs/2607.01793
- **一句话核心**: 提出了一个三维风险分类法（危害后果 × 攻击方法 × 执行环境），并从 prompt 级评估扩展到轨迹级评估框架，发现多轮重表述可使 ESR 差距达 +24.8 点。
- **为什么重要**: 提供了 scale 化的 agent 安全测试方法论，实际测试发现多轮攻击效果远超单轮。

### 11. AI-Infra-Guard Technical Report
- **链接**: https://arxiv.org/abs/2606.31227
- **一句话核心**: 统一的多层红队框架（基础设施 → 技能供应链 → 应用层行为），实现了能力感知的成本约束黑盒测试，并首次将 Prompt-as-Rule 审计引入 MCP 技能供应。
- **为什么重要**: 覆盖最完整的 agent 安全审计框架之一，特别在技能供应链审计方面是开创性的。

### 12. A Lifecycle and Application-Stack Survey of LLM Security
- **链接**: https://arxiv.org/abs/2606.31639
- **一句话核心**: 从生命周期视角系统化 LLM 安全——指出"投毒"一词不充分，因为被投毒的对象在变化（预训练数据、对齐数据、RAG 语料、工具描述、记忆、评测基准等）。
- **为什么重要**: 为整个领域提供了统一的概念框架和术语体系，是难得的系统性综述。

### 13. HaloGuard 1.0: An Open Weights Constitutional Classifier for Multilingual AI Safety
- **链接**: https://arxiv.org/abs/2607.02079
- **一句话核心**: 开源的多语言宪法分类器（输入护栏），但明确声明不保护 agentic 全景——不检查工具调用、权限、文档验证或执行轨迹。
- **为什么重要**: 清晰划定了"输入护栏"的边界，提醒社区 agent 安全需要更多层次的防御堆栈。

## 🧠 记忆安全（6 篇）

### 1. Forged Reasoning Attacks on LLM Agent Memory and Defenses (FARMA)
- **链接**: https://arxiv.org/abs/2607.05029
- **一句话核心**: 提出一种新型记忆攻击——不是投毒记忆内容，而是伪造 agent 的"推理轨迹"让 agent 相信某些安全步骤已执行完毕，从而跳过验证。
- **为什么重要**: 这种攻击不依赖 overt 恶意指令，而是篡改 agent 对"自己过去做了什么"的认知。对 EHR、金融等需要审计链的 agent 系统威胁极大。

### 2. MemSyco-Bench: Benchmarking Sycophancy in Agent Memory
- **链接**: https://arxiv.org/abs/2607.01071
- **一句话核心**: 首个系统评测记忆诱导谄媚（memory-induced sycophancy）的基准——agent 因检索到历史用户偏好而放弃客观事实、对齐用户错误认知。
- **为什么重要**: 现有记忆评测只关注存储/检索/更新正确性，忽略了记忆对推理决策的负面影响。这个基准覆盖了 5 类关键任务场景。

### 3. DriftLens: Measuring Memory-Induced Reasoning Drift in Personalized Language Models
- **链接**: https://arxiv.org/abs/2607.02374
- **一句话核心**: 构建框架测量个性化记忆导致模型推理漂移的程度——发现记忆不仅仅是改变了"答案"，而是改变了推理过程本身。
- **为什么重要**: 记忆导致推理漂移是一个被严重低估的问题。这篇工作对记忆中毒和记忆谄媚提供了定量测量工具。

### 4. ElephantAgent: Contextual State Continuity in Agentic Systems
- **链接**: https://arxiv.org/abs/2607.01919
- **一句话核心**: 提出通过强制记忆连续性来防御记忆投毒——任何未经授权的插入、删除或篡改都能被检测并阻断。
- **为什么重要**: 提供了实用的记忆完整性保护方案，论文还系统梳理了当前记忆投毒攻击谱系。

### 5. KidnapRAG: A Black-Box Attack for Hijacking Reasoning in Agentic RAG Systems
- **链接**: https://arxiv.org/abs/2607.00422
- **一句话核心**: 通过顺序投毒文档逐步劫持 agent 的多步推理意图——不是"一次注入"而是"逐步引导"agent 偏离原任务轨迹。
- **为什么重要**: 传统 RAG 中毒攻击失败是因为 agent 会回到原问题，KidnapRAG 通过链式推理操纵阻止这种恢复，对 agentic RAG 系统构成实质威胁。

### 6. Memory-Induced Tool-Drift in LLM Agents
- **链接**: https://arxiv.org/abs/2605.24941
- **一句话核心**: 发现 agent 的记忆会导致工具选择漂移——历史中使用的工具会影响后续任务中的工具选择，即使这些工具不适合当前任务。
- **为什么重要**: 记忆不仅在"内容"层面影响 agent，还影响"工具决策"层面，这是记忆安全问题的一个新维度。

## 🔧 Skill 安全（5 篇）

### 1. Cloak and Detonate: Scanner Evasion and Dynamic Detection of Agent Skill Malware
- **链接**: https://arxiv.org/abs/2607.02357
- **一句话核心**: 发现攻击者可以制作能逃逸静态扫描的恶意技能包（通过条件触发、编码混淆等），提出运行时动态检测方案。
- **为什么重要**: 现有的技能安全扫描（如 MalSkillBench、Skill-Inject）基本是静态的，这篇工作证明静态扫描可以被系统性地绕过，动态检测成为必要。

### 2. Skills Are Not Islands: Measuring Dependency and Risk in Agent Skill Supply Chains
- **链接**: https://arxiv.org/abs/2607.01136
- **一句话核心**: 从供应链视角分析技能生态——不是研究单个技能的漏洞，而是技能之间的依赖图、权限传递和风险可达性。
- **为什么重要**: 技能不是孤岛——一个下游技能的漏洞可能通过依赖链传递到上游，社区需要综合治理而非单点修复。

### 3. From Anatomy to Smells: An Empirical Study of SKILL.md in Agent Skills
- **链接**: https://arxiv.org/abs/2607.01456
- **一句话核心**: 对真实世界 SKILL.md 文件的实证研究，识别出"技能气味"（skill smells），包括安全风险类的 prompt injection 嵌入问题。
- **为什么重要**: 将"代码气味"的概念引入技能安全，提供了可操作的静态检测指标。

### 4. The Decomposition Is the Fingerprint: Per-Component Identity for Agent Skills
- **链接**: https://arxiv.org/abs/2606.31272
- **一句话核心**: 提出将技能逐组件分解生成"身份指纹"，用于供应链完整性的验证和防篡改。
- **为什么重要**: 技能供应链中，用户安装了一个技能后如何验证它没有被篡改？这篇工作提供了可行的身份验证方案。

### 5. SkillCoach: Self-Evolving Rubrics for Evaluating and Enhancing Agentic Skill-Use
- **链接**: https://arxiv.org/abs/2607.01874
- **一句话核心**: 提出自演进评估框架评测 agent 的技能选择/组合能力，发现 agent 容易调用干扰性技能、跳过必要步骤或错误组合工作流。
- **为什么重要**: 能力控制是 skill 安全的核心——即使技能本身没有恶意，agent 错误选择或组合技能也是安全风险。

### 📌 今日重点推荐

#### 🥇 FARMA: Forged Reasoning Attacks on LLM Agent Memory
*arXiv:2607.05029*

**为什么是本周最值得读的一篇：** 它发现了一个全新的攻击维度——不是污染 agent 的记忆"内容"，而是污染 agent 对"自己过去推理过程"的认知。攻击者插入伪造的推理记录（如"上游验证已完成"），让 agent 在后续任务中跳过安全检查。这种攻击不依赖任何恶意指令、不触发关键词过滤、不需要触发词。在 EHR、金融交易、代码审计等场景下，这种攻击可以造成严重的信任链断裂。同时论文也提供了实用的防御思路，值得仔细阅读。

#### 🥈 Agents Data Injection (ADI): A New IPI Category
*arXiv:2607.05120*

**为什么值得关注：** 如果说 FARMA 攻击的是记忆层，那么 ADI 攻击的是 agent 对"可信标识"（元数据）的信任。它不注入指令，而是篡改电子邮件发件人、资源标识符等 agent 依赖的安全锚点。这意味着所有针对"指令注入"训练的防护（包括 LlamaFirewall 等）对此类攻击完全无效——这是 agent 安全防御体系中的一个系统性 gap。
