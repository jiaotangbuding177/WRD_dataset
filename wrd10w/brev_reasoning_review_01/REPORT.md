## 已发现而必须处理的负例

`REVIEW_ERRATA_02.json` 保留两类问题：我初审的一条零 loss 理由误称旧代码未检查 source/message 字符串类型，实际上该检查已存在，错误理由已撤回；原 call24/25 思考把非 list 的 `ledger_basics` 路径误说成 `$.facts[0].evidence_refs`，实际该 failure 在 `$.facts[0]`，另一个 `missing_required_evidence` 才使用更长路径。两个不同 failure 分别满足 ID 和路径断言，不能证明同一 failure 的路径正确。

初版 2,689 tokens 因此只是待修订候选。原模型后来报告 21＋12 自测通过，不能为这类错误思考背书。原模型关于“不同年份证明 genericity”、原包“干净”的过强说法均未批准；原 raw 包有 pyc，非递归 ls 不足以证明封装干净。
