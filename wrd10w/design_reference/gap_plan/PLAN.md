## 2. 先恢复原始思考归属：10位置试核，再扩展100个maker

本轮检查存续桥接源码发现：兼容响应ID和工具调用ID会被重写；`reasoning_content`也可能同时承载模型thought和进度消息。因此，“2729个兼容ID与旧provider组没有交集”只能说明该ID键未接上，不能证明原思考不存在。这个机制目前只对审查报告中指定源码SHA成立，须逐历史部署核对，不能套到所有日志。

1. 从至少两个通道、两种已知桥接冻结中选择10个响应位置：包含已有强关联的正对照及同prompt重试／并发的负对照。先验证关联方法，避免按内容相似度串错前因后果。
2. 联合原生session／request／conversation身份、observer实际provider ID、原HTTP请求字节指纹、保持数组和字符串的规范化请求指纹、实际工具映射、校准时间及响应内容。允许一对多重试／续跑；相似文本或接近时间只能生成候选。
3. 对接受的关联逐条独立复核：请求、过去观察、思考、动作、工具反馈均属于同一历史分支。10个位置均须有明确裁定，正对照应命中，负对照不得误并；失败先修关联方法，不直接批量授原R。
4. 再扩展93个已有兼容ID会话及其余7个maker，以实际原attempt目录、SDK/provider载体和有来源定位的备份为入口。C侧已定位75.56MB会话目前只是元数据入口，不预判含多少可用R；归属和保护边界先行，不扫描账号配置或凭据。

产出 `REQUEST_PROVIDER_CROSSWALK`、原始请求／SSE／thought证据副本及逐跨度来源表。至少区分原逐轮thought、累计思考摘录、进度／压缩消息、partial、不可读密文和新作者理由。**保留全部原文，不对密文猜写思考，不将新标注说成原Teacher的CoT。** 若同一桥接机制确实影响当前已批R银行，另作来源类型审计和显式更正overlay；无证据不把现有原R全部判坏。

## 4. 补完整资源和修订教学，不能靠标签伪造执行

在来源可用且材料实际齐全的旧链及391候选中，优先处理能交付完整文件的表格、HTML、文档／模板和知识索引；随后按真实可用性扩到演示、媒体等机制。先完成材料和环境核查，再确定具体source名单，不能先把候选量写成已准入量。

- 完整构建：用户需求、真实必要依赖、完整代码／模板／SKILL.md以及可复现用法配套。旧代码仍有错时可保全全文，并仅对已证正确范围授loss；不能因为文件很长或一处有错就连坐丢掉全部正确代码。
- 真实修订：恢复旧版本、真实失败、模型当时可见反馈、定位依据、原edit和新版本复测。旧失败动作和错误R保留在输入／审计中，错误跨度loss为0；正确诊断与正确补丁分别授信，避免成功状态洗正错误解释。
- 明示新标注：若缺的是状态表达或解释，可写新作者理由并绑定真实证据；若缺的是实际试用、测试或修订结果，标注不能替代执行。受控注入的新故障必须标明合成来源、注入算子和新实际检查，不能冒充历史失败。
- 先完成6–12个完整资源教学目标、12–24个**不同故障机制**的修订三元组，作为下一检查点的工程目标；实际数量由能找到的证据决定。同一程序换参数、重复片段不算独立机制。纯资源检查在固定环境中进行，不能运行旧自建Agent循环。

局部测试通过只支持局部实现信用。判断修订是否让技能更可靠、更省，需要该**同一资源版本**在真实消费中的表现与独立质量评审；没有这条边，不授整体KEEP或降本信用。

## 5. 自主调度与正向收尾：另做有界原生采集

现有链若本来由外层逐阶段派发，重新排成一篇长对话也不能变成“模型自主完成”。原记录恢复完成后仍缺的自主过程，必须通过真实原生会话补齐。以下是**拟议采集合同，本轮未派发**；不能从计划上传自动扩成执行。

首批选表格处理和本地HTML两种自包含、能在原1800秒预算内真实交付的任务。先用2场公共技术预检确认：模型能通过实际暴露的原生能力自主派发并等待消费／评审子会话；子会话资源隔离有效；原R／请求／工具映射／用量可完整记录；总预算可真正执行。工具schema中有sessions_spawn／agents_wait不等于固定容器内已经可用，cwd也不等于文件隔离。任一关键前置不成立即停在技术验证，不改用外层逐步控制冒充自主。

| 首批上限 | 数量及含义 |
|---|---|
| 路线 | 2条；完成2条原生自主闭环是目标，实际可以为0 |
| 原生会话 | 最多24场，含2场预检；每路线最多11场（父控制器＋消费／盲评，含至多1次修订） |

| 每场原生预算 | 保持1800秒／32768回复上限，不为凑完整链事后延长 |

全部组固定镜像 `sha256:97a0f55bec1ef293c15ddd5a17cc843050387bd2369dcf2fd388b1afd40810a2`、OpenClaw2026.9.5、glm-5.3-flash、原工具／依赖／原生skills发现读取和循环。外层只投递输入资源、启动原生会话、记账和事后评分，不能替父模型决定每一步、自动执行技能、伪造工具反馈或提前收尾。父会话等子任务的时间也计入其1800秒；实际平台不支持所需原生调度时报告缺口，不拼接多场冒充单场自主。

6M必须在调用前按已知输入、SDK额外前缀和最大输出预留，或用真实上游硬限额约束；如果只能事后报警，就不能声称是硬预算。usage缺失记UNKNOWN并按预留保守扣账。并发须通过宿主资源核查，不预设机器可以额外开满。这里只规定最高4容器的候选上限，不改变既有任务。

每路线的真实因果链：

`干净原会话／材料 → 父模型探索与A筛选 → B完整V0资源 → 两个真实训练消费case的NS/V0同条件对照 → 独立盲Q与成本 → 有具体缺陷才修订V1 → 同case复试 → 有依据的KEEP／STOP／HOLD与D封装`。

父模型须实际读取子会话返回并据此处理；没有自然缺陷不人为制造REVISE，结果不合算就STOP，不预定必须产出KEEP。Q须在执行前绑定适用于该case的冻结rubric、权重和锚点；缺项明确作为新提案，不冒充已有合同。Q不得看到父模型的“应该保留”结论；评分未知保持UNKNOWN，TSR与Q分报。

首批拟需10个互不共享私有祖先的source component：2制作、4训练消费、4学生留出（2dev／2test）。这是待筛定任务量，不是已选好名单。消费反馈若进入SFT，就不能再当独立学生dev/test。4个留出任务先冻结，边界变体不能虚增独立任务数，test在学生与超参数冻结后才使用；如此小的留出只适合工程试核，不足以宣称总体提升。

后续可按“再4条、再6条”扩大到12路线／最多6机制族，但必须先看首批的实际R捕获率、有效监督密度、质量与成本，再另定预算；**本计划不自动开放后续批次。** 200次请求不是200条样本，更不是监督目标数上限；上游请求、包装响应和原生动作可以一对多或多对一，采后按canonical owner去重统计。6M调用tokens也不是6M正监督tokens。

## 6. 数据如何接到14B／8B训练，而不是只把日志喂进去

主模型和对照沿用检查点07已固定的Qwen3-14B／Qwen3-8B及revision；BF16冻结基座、LoRA r32／alpha64／dropout0.05、七投影和lr5e-5等配置保持候选。当前57／最多115更新仅适用于旧552行组件pilot，**新增数据实际编好后必须重算，不能现在宣布新主训练步数、小时数或效果。** Spark的ARM64／GB10实际算子、内存、selected-head梯度等价和长窗验收仍是训练前工作。

新数据按教学职责分银行：来源契约辅助、原R／原动作复杂过程、明示新状态资源构建／修订、原生自主控制器、独立消费与质量评审。主控制器训练需要真正的父会话动作；不能用消费Agent大量业务执行充当自主制作的主数据。契约和浅层读取不再主导新增曝光；完成新过程银行后再按来源／机制／阶段定配比，不靠反复过采样现有少数复杂链解决缺口。

训练的条件关系是“截至当前观察→下一步R／动作”，用后续同版本结果审核信用：

| 证据链 | 监督内容 | 预期可学能力 | 必须证伪的失败 |
|---|---|---|---|
| 需求及多轮纠正→探索→资源选择 | 需求继承、原R中有依据的选择、真实工具操作 | 读会话后自己发现资源并筛路线 | 只复述要求，不实际操作；修一项丢另一项 |
| 完整资源→真实错误→同对象修补→复测 | 原诊断、完整构建、局修、错误跨度mask0 | 发现失败并作有效修订 | 复述“成功”但代码仍错；修了别的版本 |
| 同case NS／Skill→盲Q→完整成本 | 有证据的KEEP／STOP／HOLD和边界 | 质量与开销共同驱动取舍 | 只看completed或低token就KEEP |
| 原生父会话→实际子任务→返回→继续／结束 | 真实调度动作、等待与分支 | 在环境中自主推进全pipeline | 外层不提示就停；把计划文字当执行 |

主方法是**按结果审核信用的因果过程SFT**：保留前因、原始思考、动作和反馈；分辨正确推理与错误推理，局部信用与整体效果。mask0的错误上下文仍进入因果attention，完整历史不等于全部正loss。原逐轮R、累计摘录、新作者解释分账；新状态银标沿用0.25候选权重，不通过按权重和归一抬回1。每个owner的core／full／新状态视图互斥曝光，避免同一内容多次计量。

loss仍按整个optimizer step的有效shifted标签数归一：`sum(weight_t * CE_t) / N_valid_shifted_labels`，只监督经外置审查批准的跨度。未来Q仅放信用metadata，不放进过去输入。只有同状态、同需求、同版本条件下具有真实结果差异的候选才可另建偏好对；本轮不预设DPO／RL，也不把不同任务的成功失败硬配成偏好。

16K／32K共同视图重编两模型实际tokenizer并验证；完整53工具原生视图另报full32／64／128覆盖。必要过去太长时保留全链并进条件长窗，不能截掉失败或依赖来“覆盖32K”；64K位置扩展、128K服务总窗与32768输出预留须单独实测，不能与训练桶混为一谈。

模型最终接口仍是：输入原会话、当前任务、真实可访问资源与权限／预算；输出原生工具调用并消费真实反馈，迭代形成技能目录、可复现资源及有证据的结束决策。SFT让这些条件关系有机会被学会；**是否能自主迁移、比基座更好、成本更低，必须用留出任务实际运行检验，不能由记录了CoT或写了方案推出。**

## 7. 下一检查点怎样算真正交付

历史恢复与新采集分成独立里程碑：历史批先完成并上传，不等待新采集；新采集技术预检和业务结果分别交付，技术失败也提交真实原件和费用。任何阶段未执行，报告中明确为0或未执行。

1. **全量覆盖账与恢复包**：逐owner覆盖表，10位置身份试核报告，196逐项裁定、原始R／工具／返回／资源实体及证据路径；对实际可用内容交付正文和训练行，而非只给候选地址。
2. **真实训练银行**：逐行完整输入／目标、跨度loss mask、owner／source／作者身份、资源SHA、信用层级和外置准入回执；原件、被否定跨度及旧版本仍在audit，不进默认通配训练。6–12构建、12–24修订是目标，必须报告实际达成值及缺口。
3. **闭环证据包**（仅采集实际发生后）：目标2份完整候选资源、4个同case的NS／Skill对照、实际独立Q和成本、真实终态；发生修订才交付V0→失败→V1→复试。报告0–2条实际完整原生自主链，KEEP数量不设保底。两条成功也只是方法与采集机制试核。
4. **共同训练QA**：两tokenizer／全部loss mask／owner去重／226+H12+static及新留出隔离／标准loader／canonical数组实际检查；分别列16K、32K、完整原生长窗覆盖和未容纳原因。
5. **量与阶段表**：实际样本、正监督tokens、原R与新R、独立来源与机制、完整代码、已证修订、真实试用、KEEP／STOP／HOLD、自主链分别计量；数据覆盖和效力评估分开。2000目标／百万监督／50来源／12机制只保留作旧工程扩充里程碑，不当充分性定理。
6. **Git真实交付**：增量实体、还原说明、唯一训练入口和来源／质量报告；实际还原及远端字节SHA核验后才说已上传。不能把本计划的发布当作新数据检查点08。

## 8. 质量与每个合格技能总成本如何判

后续学生比较base14B、SFT14B、base8B、SFT8B，使用同一任务、原生工具／发现读取、预算、服务窗口和Spark条件；先过组件检验，再做独立原生完整任务。主要报告交付TSR、独立五维Q、实际资源使用、修订成功、错误保留率和自主完成率；dev选模型，test不参与调参，原226不反哺。

同时给边际沉淀成本与总成本。总成本包括数据恢复／AI标注、Teacher及失败采集、环境、训练、开发评估、全部尝试／修订、工具、人工兜底，再除实际合格技能数。GPU小时、经过时间、token／调用、现金和能耗分列，未知不是0；合格数为0时单位成本未定义。

单技能复用情景事前固定，例如N=20并另报1／5／100敏感性：若单次消费节省 `c_NS-c_S > 0`，收支平衡复用次数为 `ceil(C_fixed/(c_NS-c_S))`；不节省则没有有限回本次数。N是工程情景，不是已经证实未来会复用20次。独立Q、交付、实际读用和成本不完整时不作“合格且降本”结论。

这条方案的因果主张是可检验的：完整前因与正确过程帮助学动作；同版本反例与修复帮助学纠错；真实对照与Q／成本帮助学取舍；原生自主轨迹帮助学调度。四类证据缺任何一类，相应能力就仍缺训练依据。全部补齐也不能预先保证达到理想模型，最终以新来源原生执行的质量与每个合格技能总成本判断。
