# WRD11：可验真的构造数据、过程授信与验证设计

2026-10-31。本文为本轮构造方法和评价建议，基线是检查点10及设计5.0.52；不把建议写成新增样本、实际原生运行或模型效果。双稿版本与最终数量由本轮主负责人按实际产物同步。本轮不启动训练、模型forward/backward或新业务Teacher／Actor／native采集，原226和新旧保留来源继续隔离。

## 现有数据需要补什么

当前主集623目标／227233正监督tokens，其中418是契约辅助、205是过程；过程只有56来源ID／44全局连接组。过程按阶段归并为A5、B158、C11、D5，另26历史workflow R。原R-only46条仍保留，当前原兼容R＋动作／业务D配对24视图只覆盖5来源／3组。主manifest、分片元数据及本轮前的[实际报告](../20261031_wrd_curation10/ACTUAL_DATA_REPORT.md)支持这些数量。

构造最应补C—D的版本归因、消费对照和收尾边界，以及父控制器的状态转换。继续将同一写程序动作改名，或只把“需要验证、应当HOLD”换说法，不能填补这些缺口。新增构造case数、构造机制族数、真实来源组数必须分开；给44组制作很多变体不会增加独立真实经历。

这些来源共同支持一个方法判断：可构造数据，但应扩展可辨识的状态／动作／后果关系，并对新数据实际验真。它们没有证明当前205过程或任何预先指定的构造数量足以实现全自主沉淀。

## 三类数据分账

1. **原记录恢复。** 原会话／原API字段／动作参数／实际反馈逐SHA和偏移连接，保留原推理条件；未闭祖先、错误跨度和后验倒灌不因新构造被洗正。原始思考继续保留，恢复量单独报告。
2. **资源支持的构造。** 使用允许TRAIN来源的某个具体资源版本，或本轮新建的公开通用fixture，实际在CPU执行程序和正常／边界／错误输入；生成完整点时状态、目标动作和可复现结果。原资源、新输入、新动作投影、新解释分别标记。局部测试只能授局部资源信用。
3. **程序化决策构造。** 给出明确、有限的假设状态和任务内判据，独立计算应读什么、能否消费比较、继续／修订／HOLD／STOP等标签。这里的“模拟KEEP”仅是构造规则下的决策，不能增加真实合格KEEP或原生完整自主轨迹数量。

没有实际执行的工具返回必须标`constructed_observation`，不能标`native_tool_result`。把多个已记录阶段接成一份监督序列时，必须标`constructed_workflow_sequence`，不能改称同一个原生父Agent自主完成。数据整理脚本不替代OpenClaw的原生工具／发现读取／会话循环，也不向任何实际组注入另一套Agent执行协议。

## 本轮可构造的case族

| 因果机制 | 需要提供的可见输入 | 目标／反事实 | 可用的CPU验真 |
|---|---|---|---|
| 先探索后行动 | 真实或构造目录、候选文件清单、缺失的必要内容 | 在不知道具体内容时选择读取，获得内容后才选择制作；新增提示文字不改变旧事实 | 路径存在、文件SHA、需求字段来源与读取前后可见性 |
| 原生工具ABI | 当前冻结工具schema、同一操作的原参数 | 保留`edit(path, edits[])`等实际ABI；错误形状不能为正例 | JSON schema、精确参数和定位命中；不把schema通过说成真实执行 |
| 资源补丁与反例 | 旧代码／模板、具体缺陷触发输入、允许的修改范围 | 新程序修正该反例并保留正常行为；恢复旧行应重新失败 | 独立测试器运行旧／新程序及回退mutant，保存stdout/stderr与输出SHA |
| 异步任务状态 | 实际可见的job ID、排队／运行／终态receipt和预算 | 未终态先等待／读日志，终态且有效后才消费；超时不自动重新派发 | 状态引用和时序一致、原生工具参数schema；不声称本轮真的派发了子Agent |
| 同版本效用比较 | NS、V0、V1资源SHA与逐case真实／构造receipt | V0成绩不能授V1；改成同SHA且完整观测后才可形成有效比较 | 按完整复合键连接(case, model, environment, resource_version)，拒绝跨版本配对 |
| 质量与成本冲突 | 同case交付、独立Q向量、包含失败／修订的费用与阈值 | 只省token但质量下降不能自动保留；只补一项缺费字段应改变“未知”而非改其他事实 | 独立十进制计算与单位换算；判据必须作为该构造任务的假设，不校准生产Q门槛 |
| 独立性与重复经历 | 不同ID却相同内容、多个case共享祖先、重复版本 | 去重后计独立n；重复运行不变成新来源 | 内容指纹、共享祖先DSU、group级计数 |
| 包装与消费前置 | SKILL.md、scripts/assets/templates/references和相对引用 | 文件齐备但入口参数错误仍不合格；局部修复后仅授相应阶段 | 实际临时包引用解析、公开CLI正常／边界／错误输入；不修改活跃skills库 |
| 缺证据的诚实收尾 | 缺manifest、缺消费者反馈、缺Q或缺费用中的一种 | HOLD说明具体缺口；全部已知但证据显示无收益时可STOP；不总输出HOLD | 对必要字段及有限任务内规则独立判定，检查标签和可见证据逐项对应 |

一个case族需要包含不同语义分支，而不只是多组随机数。应有“缺件后重读”“证据补齐后推进”“真实反例后修订”“明知不值得继续而停止”等可判别变化。保持原205过程的制作／修订信息，不能为了补C/D而将新数据全部变为停止标签。

## 因果链与标注约束

每个样本按`point_state → rationale → action/decision → versioned_observation → credit`保存，其中当前输入只有`point_state`及已经发生、已经送达的观察。

- **点时边界：** 更晚的成功／Q／KEEP可用于审核当前目标是否授信，不能进入此前输入。未来修复版本的代码、测试答案、预期决策和`expected_*`字段也不得进入当前输入。
- **解释约束：** 新理由逐事实引用可见输入中的键／文件／receipt，并只写完成该决策所需的因果说明。标记为`new_authored_causal_explanation`；不冒充教师原CoT，不靠更长文字增加正确性。
- **范围授信：** 工具参数可执行、局部资源正确、完整交付、独立Q和复用效用分别判定。只有具体错误范围零loss，不能因终态成功将整条旧轨迹授正，也不能因最后HOLD取消此前正确局修。
- **对照干预：** 同一基础case至少提供一次能改变合理动作的条件干预，并提供一次应保持动作不变的扰动。后者包括重排目录、无意义ID更名、无关日志追加；仅换措辞不是新增因果覆盖。
- **规则公开范围：** 合成任务可以明示判据，但输入不能直接含“本题标签=HOLD”。判据是有限训练任务定义，不是WRD真实生产门槛已校准的证据。
- **来源边界：** TRAIN真实资源继承全部已知来源祖先；纯新fixture使用独立的构造来源命名空间。真实dev/test和原226不作为seed、正确答案或阈值来源；保护材料仅用于隔离检查。

标签至少应有：`origin_kind`、`source_pins`、`source_or_generator_group`、`mechanism_family`、`base_case_id`、`intervention_id`、`split`、`point_state_sha256`、`resource_before/after_sha256`、`oracle_version_sha256`、`execution_evidence`、`validation_scope`、`rationale_provenance`、`negative_spans`、`counts_as_real_native_demonstration=false`。构造KEEP还需`counts_as_observed_qualified_KEEP=false`。

## 验证器必须检查生成器可能犯的错

同一函数既生成标签又检查标签，只能证明程序自洽。建议独立编写oracle或由独立审阅者重新计算，并保留以下负例：错误版本SHA、错case连接、缺费用被当0、缺Q被当0、跨单位费用直接相加、退出码0但内容错误、未来字段泄漏、重复来源被算独立、反事实只改无关字段却翻标签。资源修复类需让旧代码真实失败、新代码通过，并确认回退修复可再触发失败。

入库至少分六层：来源与split；点时和字段泄漏；结构与实际ABI；有限oracle／真实CPU资源结果；独立语义复核与干预有效性；14B/8B分别tokenize、mask及实际四features。未过前五层不能靠第六层的数组正确转正。

构造测试集应先冻结，再生成训练变体。同一基础case、资源、生成器结构及反事实两臂全部留在同split；仅随机打散行会造成模板泄漏。测试须留出部分机制组合、输入布局和资源实现，并单列TRAIN同族变体与未见族表现。解析器不应从ID、目录名、固定句式或“缺几个字段”直接读到标签。

## 训练与评价的接线建议

原记录、契约辅助、资源支持构造和纯规则构造分银行。新作者／再情境／构造目标沿现行银标0.25候选，不借权重归一化把0.25除回1。合成按有效加权监督曝光报告，额外提出10%／25%合成曝光上限作候选消融；这些比例是待dev检验的研究建议，不是已证最优值，也不自动改现行训练配置。按来源／机制族采样和pass结尾flush，不能用几百短合成决策淹没长原过程，或让低来源组曲线预先看到全域构造素材。

先分别比较真实过程、真实过程＋构造、同状态R＋A与重渲染A-only；R-only保留在默认过程银行，但不混进要求共同A owner的思考因果消融。最终对照还需同目标曝光的14B／8B和基座；任何训练均未在本轮启动。

评价层次应为：

1. **数据验收：** 实际准入目标、真实来源组／构造机制族、正tokens／加权曝光、错误率、反事实翻转一致性、无关扰动不变性、窗口／mask覆盖。
2. **组件学习：** 留出族的工具选择、参数、版本连接、计算、恢复和收尾决策；不能只报告训练标签的文本exact-match。
3. **原生自主：** 经固定OpenClaw真实发现读取／工具／会话循环运行完整未见父任务，检查自发探索、子会话调度、反馈恢复与终态，记录多次运行的可靠性。本轮没有这种新执行。
4. **技能效用：** 同一冻结技能版本和独立消费者上的TSR、独立五维Q与完整成本；局部fixture通过、构造KEEP和单步决策准确率均不增加真实合格技能分母。

当前完整原生自主示范、真实合格KEEP、完整WRD学生评价仍为0；K=0时每合格技能总成本未定义。构造数据预计能够增加可训练状态与纠错决策的覆盖，这是研究假设。是否迁移为用户期望的完整沉淀能力，仍取决于上述独立原生与效用评价，不能在数据整理阶段保证。
