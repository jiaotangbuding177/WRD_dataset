# 第11轮曝光卡独立核验

最终接受的是`exposure11_final/`，不是最初的`exposure11/`。核验直接逐SHA读取原623主集全部分片、两profile各627条编译记录，以实际input_ids长度、supervision spans、权重和ID逐step重算，没有用SUMMARY自证。

原623主SHA保持`9aace2dc6b39d0dde3bafbf9f7f3d6763e485609017dd70a5c40c17a2c30277e`。从全部623构建全局source/group连接图后，既有过程池为205目标、56来源ID、44全局连接组。这个池保留原来的来源构成，不代表205条完整原生沉淀。

## 拦下并保留的排程问题

旧`exposure11`各总量、pool、正tokens和pair闭包成立，但full53和budget两profile的pilot有113/136个step的目标ID序列不同，full有209/209个step不同。原因是同seed下组内原始文件顺序不同；预算分片的16K／32K分类改变了输入顺序。该差异会给profile比较加入顺序效应。

root保全旧文件后，重新按group名和组内target ID排序再shuffle，生成`exposure11_final`。现两个profile所有real-only、pilot、full的逐step ID／pool顺序均一致；仅同目标的声明条件接口和相应序列长度不同。旧发现和旧卡核算都保留在`INDEPENDENT_EXPOSURE_QA11.json`，没有覆盖成旧版也通过顺序控制。

## 权重与接口边界

pilot加权正监督41766.55＝既有过程40148.25＋辅助1618.3；full为43510.85＝既有过程40642.75（含4次重复）＋辅助2868.1。辅助全局加权量占比约3.87%／6.59%，符合全局20%上限。

这不保证每step辅助占比≤20%：pilot有53/136个step超过20%，full有91/209个，最高分别约77.06%和81.29%。这些只是监督token权重的账面比例，不是梯度范数、Adam贡献、效果或GPU成本实测；每步有一条既有过程也不能推出每步梯度主要由既有数据决定。

两profile是同627目标的互斥条件接口，不能相加成1254目标。budget构造使用已知离线目标结构选择无工具条件题；它不是推理时根据未知正确答案选择工具目录的路由器，也没有改变原生工具环境。其质量／成本收益须在真实未见dev与完整53接口下另比较。

本核验未启动模型、优化器或原生业务调用。所有更新数都是候选计划，未以卡片存在证明完整自主或合格KEEP。
