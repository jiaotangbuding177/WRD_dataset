## 1. 需要回答的两个问题

1. 相同领域数据和原生制作过程下，14B-SFT能否比8B-SFT制作更可靠、适配更准确且可实际减负的skills？
2. 将训练、失败、修订、验证、人工和教师兜底计算在内，14B每产出一个合格技能的总成本是否更低？

模型规模不是最终目标。14B是主候选，8B提供必要对照；如果14B没有足够质量收益，或其额外费用不能被较少失败/兜底抵消，应如实保留这一结果。训练损失下降、技能数量和单次推理价格都不能单独回答上述问题。

## 2. 设备条件与选择

设备为用户报告的DGX Spark：GB10 Blackwell、aarch64、Ubuntu24.04.4、驱动580.159.03、宿主CUDA13.0、约121GiB统一内存、报告可用115GiB、约3.1T可用磁盘。此信息未经本轮远程实测。CPU和GPU共享同一内存，不额外叠加一份121GiB显存。

主模型和对照均选标准文本稠密Qwen3，避免规模比较同时引入视觉模块或混合注意力架构变化。

## 3. Spark训练环境与运行边界

候选训练容器为 `nvcr.io/nvidia/pytorch:25.11-py3` 的linux/arm64变体。NVIDIA Spark官方playbook给出该镜像及Transformers4.57.1、PEFT0.18.0、TRL0.25.1组合，可作兼容起点；它是公开教程依据，不等于两款模型已在本机通过训练。[官方playbook](https://github.com/NVIDIA/dgx-spark-playbooks/blob/main/nvidia/playbook-pytorch-fine-tune/README.md)。

镜像含NVIDIA PyTorch2.10.0a0+b558c986e8与CUDA13.0.2；25.11为2025年11月版本。保留预装PyTorch及pip constraints，不能安装通用torch wheel意外覆盖Blackwell/ARM适配。未来冻结ARM镜像digest、Python及全部依赖版本、attention backend和驱动记录；不能用宿主CUDA目录代替容器兼容验证。[官方release notes](https://docs.nvidia.com/deeplearning/frameworks/pytorch-release-notes/rel-25-11.html)。

单机单训练进程，两模型顺序运行。先测8B小基准便于排查，再测14B；主训练次序可先14B，但最终推理比较采用分块交错顺序、记录温度和背景负载。训练与评测推理不同时占用这台Spark。Dataloader先2 workers，tokenizer预处理并行先4—8线程，避免将长前缀复制到大量worker导致统一内存膨胀；这些是待实测参数。

首轮用PyTorch SDPA、gradient checkpointing、micro batch1、packing=false、torch.compile=false；记录实际SDPA backend。长序列若落到内存开销过大的math路径，先解决支持问题，不盲目放大长度。FlashAttention、Unsloth、FP8训练、FSDP及多节点均不作为前置要求。

建议保留至少20GiB系统MemAvailable余量；同时看swap增长、进程RSS和PyTorch allocated/reserved峰值，统计之间存在重叠，不相加。持续swap或异常OOM时停止自己的计量窗口、保存日志并诊断，不能动其他业务进程。Spark的nvidia-smi总显存可能显示Not Supported，不能只凭一个GPU显存值判安全。[官方说明](https://docs.nvidia.com/dgx/dgx-spark/known-issues.html)。

原生OpenClaw执行环境与训练容器是不同职责：Spark承载训练及学生模型API，制作与业务Agent仍使用同一固定参考环境、工具与原生循环。不得因为ARM64更换某一臂的工具镜像、注入skills全文、自建Agent循环或替模型执行资源。

## 4. 数据准入与公平训练集

基础材料是已整理数据包中的主工具动作候选6,774条（制作6,200、筛选574）及最终消息候选347条（制作282、筛选65）。这些是去重计数与执行证据候选；当前人工语义gold、目标token/mask编译和独立验证/测试组均为0。

主要动作文件为 `native_actions_core7.train.jsonl.gz`，SHA256 `bf940e8a84be187b6da3288b3d13fff59ee61c10cd2849ddf126bec3ba95e885`。本目录不包含该文件。数据的原始、standard、native、core7表示重叠，文件同字节成功write也只是子集，不拼接扩样。辅助阶段、正式评测反馈、历史执行条件未核与quarantine不进入主监督。公开计划只用汇总数字与文件校验值，不发布样本。

后续先执行以下数据工作，当前仅规划：

1. 分层抽审300动作：100筛选、200制作，其中覆盖全部63个标准格式文件同SHA写入；至少20%独立复核。按工具、真实路线、修订、长度和历史结果分层，记录通过/拒绝/不确定。建议观察正确率达到95%且无关键泄漏/协议缺陷后，才考虑纳入其余银标；抽审不将全量升级gold。
2. 另审最终决策与收尾：筛选65个最终消息及可核实决策文件，保留真实批次与原schema；制作282个最终消息中审核真实交付、明确条件不足、合理终止目标。工具动作和最终决策不是相同标签单位；主SFT必须包含经审核的终态目标，防止只学会持续调用。
3. 排除无证据动作、后续信息泄漏和脱密占位值被当可用凭据的目标；失败、未知和被否定路线保留为证据，不自动作为正监督。不得用最终保留结论追认全部历史动作。
4. 对两模型各自的锁定模板全量编译，统计prompt/target/实际监督/padding token、8K/16K/32K覆盖。当前字符分布不能替代token量，历史业务累计token也不是训练token。

公平主训练集是两模型均完成语义准入、协议编译且在共同长度下完整容纳的**相同ID集合**。保持同一目标、样本顺序、epoch曝光、shuffle seed和工具列表；不得让14B多看被8B排除的长轨迹后，仍把差异只解释为规模。报告总体与分层覆盖及排除原因。除主比较，还可另报各模型最合适的实用配置，但分开解释。

数据严格全链关联形成1组。旧数据只能用于训练及同源诊断，不能随机拆动作、相邻目标或历史版本制造独立验证。开发/盲测需要新来源组、新附件、切断资源与反馈传播并查近重复；正式226/250及派生内容不用于训练、阈值、checkpoint或超参数选择。新开发/测试材料当前尚未收集。

## 5. 序列、损失与长上下文

训练单位为“实际过去前缀→当前assistant目标”。目标可以是可见工具动作、经审核的真实决策或最终收尾。仅当前completion与模板必要结束符计算交叉熵；历史assistant、system/user、工具定义和tool结果均label=-100。不监督隐藏思考，不把未来评审/最终文件倒写过去。

使用prompt/completion＋tools结构，`completion_only_loss=true`，不能仅设置assistant_only_loss便认为历史助手已被正确排除。Qwen关闭thinking时生成前缀包含空thinking标记；须验证训练模板与推理前缀一致，整条串行化后tokenize，不能假定分段BPE拼接等于整段。全量检查非空mask、目标完整、prefix无监督、tool协议可逆、EOS/截断边界，至少人工解码64个边界样本。[TRL接口说明](https://huggingface.co/docs/trl/v0.25.1/en/sft_trainer)。

训练使用统一七核心工具定义，但这不等于恢复原生全部工具/访问策略。未来原生小试要使用真实运行时工具投递，验证模型API返回的tool_calls、工具结果回环、自然结束和完整工具表的上下文占用，不能只给学生缩减工具。

长度选择：

- 主候选16,384 token，长度包括输入、工具模板、当前目标与结束符；整条放不下即单列，不截断write代码或用户纠正。
- 若总体或任一主阶段完整覆盖低于70%，优先验证双方32,768配置；70%只是规划最低覆盖建议，不意味着已充分覆盖全部领域。
- 如果双方都可32K，使用共同ID补充16K—32K长样本阶段，LR=5e-5；一遍总曝光内不把短样本再次重复为新数据。
- 如果仅8B可32K，先报告双方共同16K结果及14B未覆盖范围；不能只裁14B上下文。再评估双方共同QLoRA或新的依赖保全表示，属于新配置版本，不自动切换。
- 超32K保留原样、报告比例及受影响任务族；本轮不摘要、窗口化或伪造短prompt。16K覆盖不足而32K暂不可行时，不宣称训练已覆盖完整沉淀过程。

| 参数 | 14B主模型 | 8B对照 |
|---|---|---|

| LoRA | r32、alpha64、dropout0.05、bias=none | 相同 |
| 目标模块 | q/k/v/o_proj、gate/up/down_proj | 相同 |
| embedding / lm_head | 冻结 | 相同 |
| 首轮LR | 1e-4 | 1e-4 |
| optimizer | adamw_torch；betas0.9/0.999，eps1e-8，weight_decay0.01 | 相同 |
| schedule | cosine，warmup3%，max_grad_norm1.0 | 相同 |
| batch | micro1 × accumulation16 × world_size1 | 相同 |
| 内存设置 | gradient checkpointing=true，use_reentrant=false，use_cache=false | 相同 |
| packing / compile | false / false | 相同 |
| 长度 | 同一共同16K/32K合同 | 相同 |
| 轮数 | 1遍起；最多2遍 | 相同曝光 |

| 日志/存档 | 每5更新；约每0.25遍和阶段末存adapter | 相同 |

相同rank不等于相同adapter参数量，上表明确报告128M与87M的结构估算。训练参数是待验证起点，非官方最优结论。梯度累计须按有效监督token正确归一，末尾不足16微批也要处理，避免长代码目标与短决策目标因归一错误产生额外偏置。

主分析为固定配方比较。若实用选型需要调LR，两者都最多获得同一候选集合 `{1e-4, 5e-5}`，只用独立开发集选择，预算与费用全部计入各自模型。先跑共同首配方，再判断是否需要第二候选；不默认四条完整训练全跑。r64、全参、RL和大规模合成扩充不在本轮方案实施范围。

如果所有6,774主动作均准入、每条一遍、batch16，大约424次optimizer更新；加入收尾/决策、过滤与分阶段会改变实际数。该算术不是实际训练账，更不是耗时估计。无独立开发集时可按预注册一遍存档用于诊断，不能用同源loss挑“最佳泛化模型”。

## 7. 后续实施阶段与预算

以下全部待后续执行授权；本次上传计划不授权启动这些工作。

| 阶段 | 工作 | 拟议边界与交付 |
|---|---|---|
| P0 | 数据语义准入、终态目标、模板/token/mask、新来源准备 | 共同ID清单与覆盖报告；保持旧包不变 |
| P1 | ARM环境检查与两模型长度桶前后向计量 | 每模型先不超过2小时、合计4设备小时；超时保留已测，不自动加预算 |
| P2 | 两个独立smoke adapter | 每模型128—256已审样本，最多2遍且32更新；不继承到主训练 |
| P3 | 两模型主SFT | 从各自原基座重新开始、共同样本1遍；最多2遍需开发证据 |
| P4 | 新来源开发与有限LR选择 | 先主比较三臂，再有限base消融，所有费用记账 |
| P5 | 冻结盲测及独立质量/成本报告 | 先功效与预算复核，再按预注册范围；未获执行授权不运行 |

P1长度桶4K/8K/16K/32K，建议每档10预热micro steps、30计量micro steps；这些步骤已含训练计算，需要未来授权，也计成本。预算内做不完某桶就标未测，不用低长度速度代长长度性能。正式总预算在P1后由实测形成范围；目前吞吐、token总量、峰值内存、电耗与时长均未知，不能预报几小时训练完成。

`预计训练秒数 = Σ(桶内总处理token / 同配置实测训练token每秒) + 未包含的加载/存档/验证开销`

masked前缀仍参与计算，须同时记录总处理token/s和监督token/s；不能仅用监督量估时，也不能用推理decode速度估训练。例：假定总处理1亿token、实测500 token/s，则纯训练约55.6小时；这只是公式演示，不是对GB10或14B的性能承诺。

电耗以插座整机电表kWh为主，另记录设备遥测范围。空闲10W、SoC TDP、额定电源或FP4稀疏推理规格均不能替代BF16训练测量。本地设备占用、人工、电价与API单价分开，不以“自有硬件”记零成本。

## 8. 核心评测与选择规则

详细定义见[EVALUATION_PROTOCOL.md](EVALUATION_PROTOCOL.md)。主制作臂为教师T、8B-SFT、14B-SFT；8B-base和14B-base用于各自的训练增益消融。下游业务Actor固定，同一任务比较无技能及各制作臂技能，环境与预算相同，只有技能资源变化。

建议开发6个新工作流来源组：先三主制作臂18次制作、四消费臂24个基础槽位；固定其中3组加两个base臂，另6次制作/6个消费槽位，总24/30。完整五制作臂开发为30/36，可在预算允许时另选，不能和24/30混记。

盲测主比较建议24个新来源组，每组2个独立消费任务：三主制作臂72次制作、四消费臂192个槽位；事前固定6组补两个base臂，另12制作/24消费，总**84制作、216消费槽位**。base增益仅6组为探索性。完整五制作臂全24组是120制作、288消费；属于额外预算方案，不自动全做。这些是初次制作及消费基础槽位，不含后续资源修订和真实失败重试；次数与成本另列，不能冒充硬总上限。

上游制作失败仍保留分配来源与失败，不执行伪装的学生消费，不凭空写Actor请求或费用；同时报告端到端交付率与实际启动Actor条件下TSR。24来源组并不保证非劣检验功效，按来源组配对区间报告；区间过宽则未确定。新来源和评分材料当前不存在，不能把计划数量写成实际样本量。

“合格”分三层：资源与业务质量通过K_Q；现行可靠/复用/交付/账齐且业务Token及调用双降确认K_R；本方案主成本分母K_G取两者交集。分别报告三者，不把可打开、文件数或自然结束当合格。Q独立报告而不乘TSR；K_G的研究统计定义不会写入旧生产管道或倒改历史结果。

主指标：

`每个合格技能运营成本 = 全部分配来源的制作、失败、修订、资源复现、资格消费、评审、人工与规定共享费用 / K_G`

`首批含训练总成本 = (新增共同准备投入 + 该模型全部训练/试点/调参 + 本批运营成本) / K_G`

若K_G=0且成本已发生，单位成本记“无合格产出/不可回本”，不能记0；存在缺账则报已知下界和unknown范围，不能给完整可比点值。纯学生与教师兜底策略分开；教师接管后的产物不得计为纯14B或纯8B合格。

质量建议目标是学生相对教师Q不劣超过5/100、TSR不劣超过5个百分点，首批计划中每合格技能运营成本相对教师降低30%作为待验证目标。14B和8B之间不预设14B必胜：先判断质量和关键错误，再比较含失败/兜底的单位成本及训练摊销。具体分数阈值须先做人类校准、在看盲测输出前冻结；未校准Q只作探索性。

## 9. 决策、发布与当前状态

后续结果若14B质量更好且每合格技能成本更低，采用14B；若两者质量在预注册容忍范围内且8B成本更低，保留8B作为经济部署候选；若14B明显更好但更贵，报告质量—费用权衡与部署量回本条件，不擅自用一个平均分掩盖。两者均未达线则不以便宜理由部署。

计划交付不包含可执行train入口，没有连接Spark、安装依赖、下载权重、运行tokenizer或GPU前后向，没有教师/Actor/Judge新业务调用，也没有后台自动化。当前模型参数、tokenizer资产校验为官方文件只读检查，不能当训练成功。Codex整理与方案自身计算费用未知，未记为零。
