# WRD全流程蒸馏计划：14B主模型，8B对照

2026-10-25；wrd-fullchain-distillation-plan-v3。**只制定方案、扩充离线证据和标注，不启动训练。** 本计划替代此前仅以make/screen动作为主体的数据范围；旧93条保留为技术诊断子集，不再作为主训练入口。

## 1. 要训练出的能力

把用户提供的WRD图中已经使用的 **A轨迹归纳与复用筛选→B工作流与资源构建→C真实试做、质量与开销评价、局部修订→D技能封装与冻结** 作为学生的能力结构。训练对象是这条过程中的模型决策与可复用操作，不只是最终SKILL.md，也不只是下一次read/exec。

交付目标是一份Qwen3-14B领域adapter和同配方8B对照adapter：在原生OpenClaw中，能根据完整企业来源及当前资源状态，归纳路线、选真实试做需求、构建可复现资源、读取有/无技能试做证据、选择retain/revise/reject/defer，并完成轻量技能封装。模型权重、短阶段提示、原生工具与外部验证共同实现原pipeline；实际执行和双臂验证仍保留，不能用学生的一段自评文字代替。

“学会pipeline的思考”具体落实为：识别证据与用户纠正、比较有依据的方案、说明当前决策的简短依据、提出验证办法、依据真实反馈修改，以及知道何时停止。已经记录的分析原样保留；新增依据摘要标为派生标注。原CAS实际检查3817个request、1807个response和1763个session_events对象，在已检索字段/标签中未发现显式推理正文；1579个response中的thinking字符串全部是off配置。可见解释文本实际有9723条，其中沉淀角色6045条，先充分利用这些记录，再补有证据的决策摘要。未记录的教师内部思考、logits及未做过的反事实结果不补造。检查范围详见[内容盘点](CONTENT_AND_MASK.md)，不把没有检出特定字段外推为教师内部没有思考。

## 3. 先重建决策过程，再形成训练记录

建立证据图：企业来源/附件→A路线判断→B具体技能版本及资源→prepare真实试做题→actor双臂执行及全部费用→review判断→make局部修订→新试做/审查→D最终包。优先使用原有job、episode、source、case、previous、review和资源SHA引用；无法证明的关联标unknown，不能按文件时间相邻就强行串链。

A/B/C/D是图中的决策状态，与日志kind不是一一对应：make含B、修订回路和D；prepare及actor属于C的取题/观察；review承载C及进入D的判断。完整阶段序列保留，跨会话转换另建显式状态样本，不能伪装成原本存在的一条长对话。

每个监督单元带：source_group、episode/parent/版本、当前状态、证据定位及SHA、历史可见范围、目标角色、阶段、原始动作/产物、标注来源和审核级别。修复前提示只能看到修复前版本；最终报告不能倒灌最早决策输入。

## 4. 标注与过程监督

三种标签分开存储：

1. **原始记录标签**：原screen决定、review决定、原case选择和资源写入。机械恢复，不提升为正确性gold。
2. **证据导出的过程标签**：当前目标、已知约束、所用证据、简短决策依据、待验证项、下一动作；本助手可补注，逐条引用当时可见消息/文件，记录annotator和derived=true。证据不足记unknown，不填写“教师原始CoT”。
3. **结果核验标签**：交付、资源可用、实际复用、全部尝试成本是否完整、retain/revise/reject/defer是否由证据支持。unknown保持unknown，模型的自信或文件存在不算验证。

先恢复并核验所有少数分支（new/defer/no_value/merge及正确停止）、347个审查判断和实际修订链；再按阶段/来源/长短/工具类型分层审核多数类。以至少120个决策父样本做标注一致性校准（覆盖A—D，不满足某分支时全审并报告缺口），其中至少20%独立复核；这120是拟议工作量，当前未完成。不能再次把这批校准样本的通过数当完整主集。

无需强行给整场打一个“成功/失败”就传播给所有步骤。失败尝试可以提供正确诊断与后续修复的训练信号；明确错误动作留在历史但不监督为正例；正确拒绝或暂缓也是正例。新指南见ANNOTATION_GUIDE.md。

## 5. 训练算法：阶段均衡、证据决策、反馈修订

主方案以同一角色条件化adapter学习A—D，默认保留原生工具协议。Actor行为另用明确角色提示作辅助任务，主要用途仍是给C提供真实执行证据；评测技能质量时固定原Actor，避免同时更换制作模型和消费模型。

### 第一段：阶段与决策SFT

先学习短而自洽的路线/需求选择、证据解释及停止决策，使用完整阶段或经过审核的状态摘要视图。建议以4K/8K短单元为起点；不是从长轨迹截去关键前因。目标包括具体决定、简短依据及下一动作，不要求冗长思考。

### 第二段：资源与过程SFT

学习16K以内完整阶段交互及经验证可行的16K—32K阶段窗口：路线→程序/模板/资料→真实用法→复现→封装。完整阶段内所有准入助手目标可计算loss；同一目标在重叠窗口只由一个窗口拥有loss，不复制前缀反复监督。

基本损失为阶段平均、父样本平均、目标token平均的NLL，避免长程序、read/poll数量压过稀少的路线与停止判断：

`L_core = 0.20 L_A + 0.35 L_B + 0.30 L_C + 0.15 L_D`

各L_s先在同一parent的准入目标token内归一化，再在该阶段parent间平均。一个原生动作只记一个主要阶段；多视图共享parent总权重，不能因导出更多视图而无意加权。阶段内稀有决定可在固定总token预算内增加采样概率，上限为多数类的3倍，同时报告原始分布、实际曝光和最终loss权重；不再叠加同样的类别loss倍率。规范化一遍指冻结预算的计量基准，不是保证每个目标恰好仅出现一次。此损失需要显式阶段/parent权重或等价batch调度，普通SFT默认全token平均并不自动实现，本轮未实现训练器。

`L_total = 0.90 L_core + 0.10 L_actor_aux`

Actor辅助仅使用来源允许、同工具协议且语义核过的实际执行目标；若没有可准入Actor目标，该项关闭并把0.90重新归一为1，不能用错误动作凑10%。把整个actor日志作为C的观察输入不占这10%的辅助正例额度。阶段及辅助权重均为待比较的起点，不是已证明最优值。

### 第三段：反馈条件修订与闭环转换SFT

输入真实旧版本、试做错误/质量与全成本证据及review反馈，目标是原生后续诊断、局部资源修改、复现计划和新审查决定。修复后结果标签可以筛选这段训练目标，不能作为修复前已知证据。只训练真正支持的改进；同时混入首版合格、正确拒绝/暂缓和无需修改的记录，防止模型一见反馈就改写。

使用语义明确的A→B、B→C、C→B、C→D转换样本。第一、二段合计以每个准入父样本一次规范化曝光为起点；第三段额外曝光预算不超过主集监督token的0.5倍。简短依据视图最多替换主预算20%，不在外面无限叠加。三个阶段共用总监督曝光预算，14B与8B相同；epoch与重复曝光不算新数据。

### 第四段：有合格配对才考虑DPO

只有同一历史输入、同一可见反馈、同资源版本/预算的可靠chosen/rejected才用DPO。旧版失败输出与收到新反馈后的新版不是天然同prompt，不能直接拼偏好；有/无技能Actor两臂也不满足同条件。当前经过同状态核验的DPO对数未知，不能把180次revise冒充180个偏好对。**主训练方案前三段已经完整，不依赖DPO**。若后续取得足量独立可靠对，再单独比较beta0.1、LR5e-6、最多一遍的短程DPO，所有额外算力计入。

后续学生自身错误上的在线收集/ReST式改进须另获执行授权。当前只离线整理，不新派教师、不启动RL，也不声称离线SFT已经解决自身错误分布偏移。

## 6. 14B与8B、Spark配置

| 配置 | 主模型与对照共用建议 |
|---|---|
| 基座 | Qwen/Qwen3-14B；Qwen/Qwen3-8B，沿用此前锁定revision，见TRAINING_PLAN.json |
| 方法 | BF16 LoRA；单模型顺序训练，r32/alpha64/dropout0.05 |
| LoRA层 | q/k/v/o_proj及gate/up/down_proj，实际可训练参数以模型核验结果为准 |
| 优化 | AdamW、主阶段LR1e-4，反馈精修LR3e-5；warmup3%、cosine、clip1、weight_decay0.01 |
| batch | microbatch1、梯度累积16、按长度分桶，单训练进程 |
| 内存 | gradient checkpointing、use_cache=false、优先SDPA；实际attention backend须记录 |
| 长度 | 4K/8K自洽短单元→16K主阶段→32K长单元；无静默截断 |
| 总曝光 | 主集规范化1遍＋修订最多0.5倍监督token；实际按冻结manifest执行 |
| 训练选择 | 同一开发来源及同一主指标选checkpoint，不能只按最低训练loss |

Spark是ARM64、约121GiB统一内存；14B BF16权重约27.5GiB、8B约15.3GiB只是权重算术，不包括激活、优化器、工作区和桌面。使用NVIDIA ARM64/multi-arch PyTorch容器，未来锁digest和依赖，不覆盖其PyTorch/CUDA栈。不能因内存足便承诺14B32K已跑通；QLoRA只作为内存不满足时的备选，需要实测GB10/ARM内核且两模型公平性另登记。

首次获执行授权后，才依次做每模型8K/16K/32K的有界前后向和峰值/吞吐计量。32K失败则暂用16K完整窗口与有证据状态视图；超长原文完整保存，不删掉困难样本假装覆盖更高。当前不连接Spark、不安装、不下载权重、不跑前后向。

## 7. loss mask与长度的明确合同

原始完整会话是母表；训练记录允许多目标，但只有语义准入、属于该窗口且角色正确的assistant输出有loss。system、user、工具返回、外部资源输入、未准入或错误历史输出以及padding全为-100。工具调用的名称与参数属于助手目标；工具返回不属于助手目标。真实生成资源可在write/exec参数中受监督，不将它们当纯工具噪声删除。

原生视图与新增“证据→决定→验证”视图分开编译；后者是已声明的新训练任务，不改写历史原生轨迹。新增摘要只引用当时可见证据。同一目标不能同时在原生视图和摘要视图悄悄获得双倍权重。

原生工具schema按每个会话当时的真实工具列表恢复，不能为了套用旧core7导出器就删除非核心工具历史；Actor尤其存在更多原生工具。缺失或协议不兼容时标为待恢复/受控，而不是伪造schema或忽略必要上下文。core7只是一层兼容性检查，不是全链路数据范围。

两模型用各自锁定官方chat template/tokenizer，逐ID核验实际渲染的input_ids、监督span、EOS/工具边界及reasoning字段；不能依赖字符串前缀长度推断mask。旧17条前缀异常需要重新定位修复或隔离，不手工假定通过。

报告至少六个分母：全部会话、非空目标、语义准入、模板可编译、共同≤16K、共同≤32K；再分原始完整窗口与派生摘要窗口。长度是输入加目标总tokens，保留输出空间；不得将32K输入再加32K输出。当前旧覆盖率仅旧子集有效，新全链路覆盖率尚未实测。

## 8. 如何证明模型学会了pipeline

先在来源隔离的状态题上评A路线/适用边界，B资源复现与接口正确性，C真实取题/证据理解/修订判断，D完整轻量封装与正确停止；再以新来源完整闭环制作和固定Actor消费验收。学生不能自己宣称retain即获得合格标签。

主比较：同期教师T、14B全流程学生S14、8B全流程学生S8。最小算法消融在14B上比较：普通动作SFT、全流程蒸馏、去决策依据、去真实反馈修订；基座与数据来源、曝光/预算一致，并报告能够控制与不能完全控制的差异。每臂的额外训练及消融成本全部记账。

沿用K_Q质量合格、K_R实际减负、K_G两者交集以及独立五维Q；不把成功率乘质量归零。拟用24个独立路线/来源组、各2个消费任务做主盲测，主T/S14/S8共72次基础制作、192个消费槽位（共享48个NS任务，只执行并记账一次）；修订、失败、重试另计。开发来源与盲测隔离，正式226/250及其后验反馈不训练、不选checkpoint、不调门槛。当前没有这些新独立测试组，不随机拆动作制造盲测。

替代目标建议：相对当期教师，TSR非劣界暂拟-5个百分点、Q差暂拟-5/100，且每合格技能运营总成本至少降低30%；K_G及其合格率同时作为主产出/成本分母报告。阈值须先校准冻结。24组只是有限探索规模，很可能不足以证明窄非劣界；必须报告配对区间和实际最小可分辨差异，不能把点估计达标写成正式非劣。覆盖不足则结论为待证，不能为达标放宽标准。

最终应得到：可替换沉淀侧模型的adapter、短阶段接口、版本化技能包、完整质量/失败/成本报告；若8B已达同样标准且全成本更低，可以选择8B。14B主模型身份不预定它必胜。

## 9. 算力与每个合格技能总成本

训练计量同时记录：唯一监督token、实际曝光监督token、处理总token（包括loss被mask的长前缀）、优化步、设备小时、峰值统一内存、整机kWh和失败/OOM。两模型不能只比较训练步数或输出tokens。未来实测r为实际长度组合下的处理tokens/s，则设备小时≈实际处理tokens/(3600r)，再加加载/验证/保存等开销；目前r未知，不编造“几小时训完”。
