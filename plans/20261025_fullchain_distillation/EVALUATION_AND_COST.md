# 全WRD蒸馏的评测、最小消融与每合格技能全成本

2026-10-25，非执行方案。本文继承[此前已发布的评测协议](https://github.com/jiaotangbuding177/WRD_dataset/blob/6151e7f2c4fb8f6130b151c9176ab411da345e39/plans/20261025_14b_spark/EVALUATION_PROTOCOL.md)、同目录TRAINING_CONFIG.json及COST_LEDGER_SCHEMA.json的TSR、独立五维Q、K_Q/K_R/K_G及费用语义。没有新测试数据、评分gold、实测GPU吞吐或训练结果；下述槽位和阈值均为拟议数量，不是已经发生的实验。

## 1. 要证明什么

目标不是“模型能复述pipeline”或“思考文本更长”。需要证明学生能在新来源上完成相同WRD阶段职责，正确运用证据、程序与资源，遇到失败作必要局修，辨别保留/停止，并以较低的全部成本交付可消费技能。原pipeline作为固定运行与对照结构保留；本实验替换其模型职责，不建立新Agent循环。

可证伪的主问题：

1. **全流程学习增益**：相同模型、独立来源与近似监督token预算下，全流程蒸馏是否比普通动作SFT提高路线判断、修订、独立质量或合格技能产出？若只降格式错误而不改善这些结果，则核心收益未证。
2. **小模型替代性**：纯S14或S8相对原教师pipeline，质量与交付是否达到预先冻结的非劣条件，同时每合格技能全成本下降？若区间过宽则未确定；不能把“教师点分的95%”直接当已证非劣。
3. **14B的经济性**：14B质量或合格率的提高，能否补偿其更多训练与推理成本？若8B在可接受质量范围内总成本更低，应报告8B更适合该部署量级。

## 2. 数据隔离先于效果判断

训练、开发、盲测按企业来源/业务实体/任务路线及资源血缘组成的关联组隔离。一个企业原会话、不同stage、资源版本、派生摘要、同一路线的改写题与失败修订不得跨split。任何由全库得出的决策摘要或资源也按实际来源追踪；新题若直接依赖训练记忆中的答案或专用资源，不能称为完全未见。

当前严格关联规则若只有1个连通组：

- 先区分真实共享任务/答案/资源血缘与“共用公共工具/同一system模板”造成的伪连接，审阅后修正边规则；记录前后连接分布与理由，不为了凑split放宽真实关联。
- 若真实仍为1组，现有资料只能训练和同来源诊断，不能随机拆动作制造独立测试。需收集新的独立来源组，或明确做按时间/新来源的前瞻测试；已有正式226/250及其反馈不反哺训练或调门槛。
- 新来源或独立质量评分未就绪时，状态为“离线整理/方法诊断完成，替代效果未验证”，不将无测试误写成无价值，也不将同源loss改善写成泛化收益。

教师只提供一个对照臂和历史示范，不自动成为真值。独立评审可认定教师路线/修订有错；其不正确输出不能因来自大模型而作为gold。用户纠正、真实附件、程序运行结果及预先冻结的业务要求是评分证据。

## 3. 两层评测：阶段能力与实际闭环

### 3.1 固定状态的阶段评测

开发建议20、盲测建议60个决策状态，覆盖至少以下六类；这些是计划，不是已恢复或已标注数量。状态按父来源组隔离，同一来源的多状态用组聚类统计，不能称60个独立任务。新状态在看模型输出前选定并冻结，稀缺决策不靠重复改写补数。

| 能力 | 给模型的历史状态 | 独立检查及失败含义 |
|---|---|---|
| A 理解与路线归并 | 用户原始要求/纠正、成功失败轨迹、当时可用路线目录 | 引用事实正确，关键条件保留，归并过粗/重复新建/错判no_value率；允许多条合理路线，不用教师字符串exact match当唯一正确性 |
| A 复用价值筛选 | 真实需求与资源可复用范围，不给未来retain结果 | reuse/new/defer/no_value的证据支持性；条件不足是否正确保留未知，不以“总选reuse”取巧 |
| B 工作流与资源构建 | 任务/来源、当时版本、工具协议、资源需求 | 步骤依赖、资源选择、公开用法和可复现性；实际复现结果单列，不按文件数/代码行数加分 |
| C 试做需求选取 | 合法演化需求池与当前技能适用边界 | 任务是否独立、可执行且覆盖适用/边界；不能只挑易题或把正式评测题拿来开发 |
| C 反馈解释与修订 | 真实两臂交付、所有尝试用量、失败证据与当前版本 | 成本算对、失败归因有据、局修范围合理、未决处理正确；不把调用exit0当业务正确，不把修订前后新反馈混作相同输入 |
| C/D 保留、停止与封装 | 当前完整证据和资源版本 | retain/revise/reject/defer是否有依据；必要文件/独立资源齐全，首页轻量、边界和索引清楚；报告错误保留与无必要修订率 |

对原生日志可比较的结构字段报告schema有效率、工具协议率、目标决策混淆矩阵、macro-F1与各类召回；对开放解释采用冻结rubric、证据span核验和独立评分。日志中机械标注只证明记录事实，不能自动提供“应当这样选”的规范性标签。新增AI标注视为待复核silver，人工复核才按记录的审阅级别描述；当前不存在新gold。

### 3.2 新来源上的完整闭环

三个主制作臂：T=原教师模型负责WRD制作/准备/审查等职责；S8/S14=对应学生承担同样职责。三个臂使用相同阶段输入、原生OpenClaw工具/容器、资源投递规则、阶段预算、同类任务池与修订上限。消费Actor仍固定参考模型及同镜像环境；没有把Actor改成学生来同时改变两个变量。Actor轨迹可作学生训练辅助材料，但主测试角色不随之变动。

学生的retain决策不控制是否进入独立评分：对全部预分配来源保留最终包、拒绝、失败、未决及所有版本。三臂均接受独立质量/资源复现检查。自己说保留不能当合格；只给学生自己保留的包评分会形成选择偏差。

若首次制作未成功，按同一事前规则允许最多4轮局部修订是建议预算；需在执行前冻结，不强迫失败案例必须修满4次。每个版本、测试、失败与等待均计费。确认未派发才记0请求；未知执行状态保留unknown。自然收尾和外层timeout分列，不由脚本提前结束降低成本。

同时记录：交付TSR、独立Q、真正资源复用/主要工作替代、局修成功率、无必要修订率、错误保留率、正确拒绝/延后率、终止合规率和纯学生完成率。正确拒绝无价值来源是正确决策，但不凭空计为一个已交付技能；按来源分母与技能产出分母分别报告。

### 3.3 基础槽位算术

| 方案 | 来源组/消费任务 | 制作基础槽位 | 业务消费基础槽位 |
|---|---|---:|---:|
| 开发三主臂 | 6组，每组1任务，T/S8/S14＋无技能消费对照 | 18 | 24 = 6×1×4 |
| 主盲测 | 24个独立来源/路线组，每组2任务，T/S8/S14＋无技能 | **72 = 24×3** | **192 = 24×2×4** |
| 可选最小消融增量 | 事前固定主盲测中6组，每组2任务，增加3个14B训练变体 | +18 = 6×3 | +36 = 6×2×3 |
| 主盲测＋上述消融 | 同上，无技能基线实际事件复用一次 | **90** | **228** |

192包含无技能48、T技能48、S8技能48、S14技能48。不是192个独立来源，也不是192个已存在的真实任务。上游没包的消费槽位记端到端未交付，并保留“未启动”；不伪造Actor事件。制作与消费栏只是首轮基础槽位，真实资源复现、修订、重试、评审调用和时间另算，不能拿72/192当总费用上限。

旧计划另有6组B8/B14未微调基座补充，得到84/216；那是另一项预算选项，不自动与本表的最小消融合并。24组不能保证非劣统计功效，独立来源不足就应报告不足，而非从同一来源切出24份。

## 4. 最小算法消融

先完成F14/F8主模型，有限消融只对14B做三项增量，使用同一基座、LoRA、来源split和工具协议。不能让全流程臂获得额外独立训练来源或新教师信息却称为纯算法提升。

| 变体 | 修改 | 主要检验 |
|---|---|---|
| F14 全流程蒸馏 | 阶段均衡、原轨迹、证据摘要、真实反馈条件修订 | 主方案 |
| A14 普通动作SFT | 同一准入来源的原生assistant动作/收尾NLL；不加跨阶段决策摘要或专门修订课程，普通按token采样 | 算法整体比仅动作模仿多了什么；不是拿旧93条做弱对照 |
| F14-no-summary | 去掉新增证据化依据摘要，保留原日志已存在的可见分析、其它数据和修订课程 | 新增依据标注是否有价值；不能把它描述为“去掉全部推理” |
| F14-no-revision | 去掉反馈→修订专门监督及修订继续训练视图，其他阶段保留；历史错误可作masked背景 | 修订课程是否改善学生错误恢复及合理停止 |

主要公平口径为相同独立来源、相同候选信息可得性、相近累计监督token与固定训练预算；同时报告实际processed tokens、supervised tokens、更新步、时长、样本曝光及差额。数据删除后为匹配曝光而增加剩余记录采样不增加独立样本量，重复暴露单列；也给自然一遍数据量的辅助结果，避免只靠训练更久解释收益。变体训练费用及失败计入科研总账，部署单模型情景只计被选方案的实际训练及预注册调参成本。

对六组消融的闭环结果标探索性，不能声称代表全部12任务类型。若经开发决定增加组/seed，需在盲测前更新计划与预算；不得因盲测不理想不断调后重报同一盲测。

## 5. 沿用TSR、独立五维Q和合格定义

TSR只验必需交付、真实格式与可打开；不因Q不够高把TSR归零。质量沿用已有schema，不另造新的五维金标：D1内容正确性与依据30%、D2内容覆盖与充分性20%、D3当前要求适配与一致性20%、D4专业判断与业务可用性20%、D5表达与呈现质量10%。条目0/0.5/1锚点，维度及Q归一到0—100。同一缺陷一个主要扣分归属，Q不乘TSR。

采用隐藏模型/训练变体/成本信息的独立评分，建议至少20%人工双审、关键错误及争议全复核；校准连续Q一致性与关键错误一致性。生产教师不同时作为唯一裁判。冻结rubric早于查看待评分输出，评分器/读取器故障为UNSCORED，不伪造真实Judge分。

- **K_Q**：包及公开用法/资源可靠，全部预分配有效消费任务交付达线，独立Q达冻结阈值、无预定义关键错误。原建议起点每任务Q≥80且D1≥80；仍待开发校准，不能看盲测赢家后放宽。
- **K_R**：资源可靠、原生确实复用、全部当前活动任务交付达线、账齐，该技能版本所有业务尝试的Token合计和实际调用合计均低于同任务无技能基线。不是每题都必须双降，也不是只看最终成功尝试。
- **K_G = K_Q ∩ K_R**：主每合格技能成本分母，每个预分配来源/路线最终至多计1；版本、副本、多文件不重复计。三值AND保持：任一false则false、均true则true、其它pending。缺账不能按0处理。该研究口径不倒改历史生产retain。

上游无包已确认失败可令该来源K为false；未评分/未知费用保留pending，除非其它证据已明确否决。纯学生与有教师兜底的策略分开，教师接管成功不计为纯S14/S8成功。阶段正确拒绝率与K_G同时报告，避免只以产包数奖励乱造技能。

## 6. 决策门槛建议及统计

门槛分三层，均为未来建议，当前无结果：

1. **可测性**：数据无真实跨split泄漏，token/mask及工具边界核验通过；测试资料/独立rubric/版本/预算已冻结，评分与成本账可追踪。未具备时不启动正式主比较，不把技术诊断当质量结论。
2. **行为与质量**：建议“关键事实/资源不可用错误不得新增”的安全条件；Q和TSR相对教师非劣容忍初始建议分别5/100与5个百分点。对学生−教师差值的来源组聚类95%区间，下界均需高于对应负容忍。阈值需开发校准和功效规划；24组区间可能很宽，结论允许未确定。不是“点估计达到教师95%”即可通过，也不是把95%置信度说成95%成功率。
3. **经济性**：建议将每K_G运营成本降低30%作为业务目标，主报告实际差/比值及区间；含训练摊销后在给定H上仍有优势才建议替代。此目标未实测、不是强行淘汰有质量优势的14B，也不能掩盖下游成本增加。

按来源组配对比较Q、端到端TSR、K_G及CPQS。bootstrap以独立来源组为单位，每次重算sum(cost)/sum(K_G)，不平均赢家单位成本；分母0的重采样保留并报告非有限比例。pending不静默删掉或判0。报告点值、组聚类区间、基座/seed/来源数、实际启动数及未知范围，不用较窄的动作级区间制造显著性。决定报告哪些检验/容忍/多重比较处理应在盲测前冻结。

## 7. Spark计量、训练成本与摊销

本机训练速度尚未测量，不给“几小时训完”的假精度。获得运行授权后，按两模型和4K/8K/16K/32K各长度桶，采用真实准入记录，固定microbatch/accumulation、软件与计时边界，测冷启动和稳态至少若干完整optimizer steps（次数与墙时上限事前锁定），GPU同步计时。以下r是训练吞吐，不是生成解码tokens/s：

`r_m,b = 实际processed input tokens / 该桶完整训练墙秒`；

`r_sup_m,b = 实际参与loss的tokens / 同一墙秒`。

同时记录前向/反向/更新时长、checkpoint和评估额外时长、统一内存峰值、GPU/CPU利用率、CPU fallback、swap读写及OOM。工具返回虽然loss=0，仍占attention计算；不能用少量监督token除prefill时间声称高训练吞吐。ARM64/GB10内核必须实测。不要拿NVIDIA FP4推理峰值换算BF16训练速度。

先按桶估时：`T_train_m ≈ sum_b(processed_tokens_m,b / r_m,b) + checkpoint_time + evaluation_time + init_time`。梯度累积包含在测量r内，不再次乘accum16。重复epoch/窗口重叠导致的实际曝光全部计入processed_tokens；预算被截停则报告实际曝光，不能冒充已完成方案。

整机电能优先用插座功率计积分：`E_wall(kWh)=integral P_wall(W) dt(hours)/1000`。若只能取GPU/板卡遥测，应注明遗漏CPU/内存/PSU，不能称整机电费。现金账为实际API费＋实际电费＋外付费用；经济账另含设备机会成本/折旧和人工，若设备小时费已含电费不得重复加电费。电价、设备单价或人工费率未知则报告小时/kWh/分钟及unknown，不虚构人民币。

令F_shared为本轮新增共同数据恢复、标注审核、模板编译和材料准备成本，F_m为模型全部计量/smoke/失败训练/主训练/有限调参/存档成本，C_op,m为全部预分配来源的制作、失败、局修、资源复现、资格消费、独立评分、人工、共享基线份额和回退成本：

`CPQS_oper,m = C_op,m / K_G,m`

`CPQS_first,m = (F_shared + F_m + C_op,m) / K_G,m`

`CPQS_amortized,m(H) = CPQS_oper,m + (F_shared + F_m)/H`

H为未来累计合格技能数，给10/50/100/500情景，不声称未来必然达到。CPQS_first是分别部署某模型的情景，同一F_shared可在两情景出现；实际科研总支出内共享事件只计一次。共享无技能/评分按事前预分配比例计入各臂，事件权重和为1，失败后不临时挪走其份额。历史沉淀成本留作生命周期账，不重复计成新训练投入；当前Codex精确成本不可得则保持unknown。

所有失败/未合格来源费用保留在C_op，不仅累加K_G赢家。K_G=0而有费用则无有限单位成本；成本未知时报已知下界和unknown事件数量。若K_min为确认合格、K_max=K_min+pending，已知成本C_known且未知费用非负，则C_known/K_max在K_max>0时可作下界；没有有限费用上界或K_min=0就不报有限上界。

若CPQS_oper,8>CPQS_oper,14且F14>F8，则两者达到同一可接受质量条件下，14B额外训练投入的回本合格技能数为`ceil((F14-F8)/(CPQS_oper,8-CPQS_oper,14))`；分母≤0则不能靠规模回本。教师比较同理。下游消费额外成本也必须入净价值；便宜制作但更难使用的技能可能总价值更差。

## 8. 最终交付结果形式

交付三个可核结果：一份能以固定原生接口承担WRD阶段职责的adapter及可复现数据/配置清单；一份含所有来源/失败/版本/未决的独立质量与闭环报告；一份按K_Q/K_R/K_G分母、含训练摊销与H敏感性的完整成本表。若不达替代门槛，交付明确的阶段能力边界和教师兜底触发策略，不宣称已把成功pipeline无损浓缩。
