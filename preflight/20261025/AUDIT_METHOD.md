# WRD 训练前审核与标签来源说明

日期：2026-10-25。派生接口：`wrd-training-preflight-v1`。对应科研设计：5.0.21 / ALG-20261025-07。

本轮处理已有 WRD 过程记录，供 14B 主模型与 8B 对照模型后续训练使用。工作包括来源核对、标签恢复、静态结构检查、AI 局部语义审核、支持材料文字提取及公开版本整理。本轮没有启动训练、加载模型权重、运行 GPU 或新派发教师、业务 Actor、Judge 会话。审核助手自身的推理有计算成本，未单独测量，不能把该项成本记为零。

本说明只含方法和汇总数字，不含企业会话原文、人员履历、认证内容或受控材料路径。下述数字是本轮已生成审核记录的快照；最终公开数量、训练准入数量、双模型 token/loss mask 和长度覆盖率以最终编译报告为准。

## 1. 历史真实记录、语义银标与准入分别记录

历史教师轨迹证明“当时确实发生过这条动作或收尾”，不能单独证明其业务判断正确、生成资源可用，或者适合作为正例。`exitCode=0`、`isError=false`、成功写文件、存在一段理由，均不等于语义合格。

本轮保留三个不同层次：

| 层次 | 含义 | 不能据此推断 |
| --- | --- | --- |
| 原生历史与来源核验 | 当前 target 与实际消息位置、历史前缀、原生工具记录、内容哈希相符 | 业务正确或内容质量达标 |
| 静态结构与 AI 局部审核 | 在明确证据范围内检查协议、实际收到的工具结果、资源语法与判断是否自洽 | 独立人工 gold、完整企业源语义已审完 |
| 公开及训练准入 | 分别通过发布检查、结构检查、审阅决策和双模型编译规则 | 公开即可训练，或装得进上下文即可训练 |

所有 AI 审阅均标注 `human_gold=false`。当前人工 gold 数为 **0**。`pass` 只在记录的局部审核范围内成立；`reject` 和 `needs_context` 均保留理由，未决不能自动转为通过。候选、可公开、语义准入、共同可容纳四种分母分别统计。

## 2. 收尾标签来自真实末条消息

从原生 canonical 会话及原候选逐条核对消息身份、event 位置、实际历史前缀与 target。恢复的 **347 条**均为实际末条 assistant 收尾消息，包含 make 282 条、screen 65 条；自然结束本身不证明交付或语义正确。

其中 **343 条**可使用真实既有 schema 规范化到统一 core7 工具集合：make 278 条、screen 65 条。core7 为 `ls/read/edit/write/apply_patch/exec/process`。另 **4 条 make 收尾**的历史涉及非 core7 工具，保留在隔离证据层；不凭空补 schema，也不伪装成 core7 正例。这四条不是被删除的历史。

规范化复用原数据包的 OpenAI 消息转换方法，并检查历史工具调用与结果配对。当前 completion 保持原 target 身份；不把最终资源追加为过去已经观察到的内容。

## 3. 路线决策有两类来源，不能混算

| 来源 | 已恢复数量 | 使用范围 |
| --- | --- | --- |
| 36 条真实 `write` 动作中的 `routes.json` 决策 | 546 个子 decision | 对既有 target 的结构化附注，保留父动作和原 target 位置 |
| 63 份最终工作区 `routes.json` 产物 | 1,292 个 decision、661 个 route 条目 | 最终产物审计、依赖定位和一致性核对 |

第一类的 546 个 decision 包含 reuse 470、new 48、defer 13、no_value 15。它们本来就在当时写出的 target 中，可以继续监督原来的写动作；**不能拆成 546 个新独立样本**，也不能为同一判断编造新的上下文。

第二类来自最终 CAS 产物，包含 new 195、reuse 951、defer 105、no_value 32、skip 9。在 65 个 screen 终态中，63 个最终产物可定位并校验哈希，另 2 个缺失，缺失状态保留。最终产物只作侧证：不能倒灌到历史 prompt，不能把后来形成的路线理由冒充当时已知证据，也不能把两类 decision 相加作为独立训练样本数。

路线审核根据当前用户要求、当时实际已有观察、当前 target、必要的历史来源与既有路线映射进行。判断理由与来源相反、覆盖缺口、证据不足等情况均可拒绝或保留未决，不因有 `reason` 字段就通过。

## 4. 静态检查与 AI 审核范围

原 6,774 个动作候选与 343 条 core7 收尾合为 **7,117 个候选 target**。全量静态检查快照发现 113 个存在结构问题的候选，7,004 个通过该层结构检查。错误包括实际 read 偏移越界、媒体内容未实际收到、写出的 JSON 无效、Python 语法错误、技能入口缺必要元数据及明确未实现退出逻辑；另有需语义复核的硬编码约束警告。结构通过仍不代表语义通过。统一去标识后的 target 还需再次检查，防止替换损坏代码或结构。

AI 一审覆盖 300 个真实动作：screen 100、make_a 100、make_b 100。审阅读取实际用户消息、最后观察和完整当前 target；必要时回查完整过去前缀或原 CAS 证据，不执行历史脚本。

| 一审集合 | pass | reject | needs_context | 合计 |
| --- | ---: | ---: | ---: | ---: |
| screen 动作 | 77 | 3 | 20 | 100 |
| make_a 动作 | 81 | 8 | 11 | 100 |
| make_b 动作 | 57 | 24 | 19 | 100 |
| 总计 | 215 | 35 | 50 | 300 |

另外对上述动作中的 **60 条**进行另一轮助手复核，每组 20 条。二审记录合计 pass 22、reject 15、needs_context 23；它们是对同一批 ID 的复核，**不是新增 60 个独立样本**。二审不同意见和后续 adjudication 另存，最终准入读取合并决策，不能把表中原始一审计数当成最终通过数。AI 之间的一致性也不等于人工校准可靠性。

收尾语义审阅已逐条覆盖 **65 条 screen 终态**：局部 pass 6、reject 12、needs_context 47。检查范围包括收尾陈述与可定位最终产物的数字、覆盖和成员映射是否相符；局部 pass 不表示全部原始企业来源的业务含义均正确。另在 278 条 make core7 终态中抽审 **60 条**，局部 pass 30、reject 13、needs_context 17，剩余 **218 条未完成语义审阅**。make 收尾的来源与协议已逐条核对，未决或未审收尾不补造人工 gold。

这些审核还发现，历史工具“成功”标志可能掩盖越界读取、内部失败或未完成资源。因此完整失败历史保留；不通过自动修正原 target、运行损坏脚本或补写未发生动作来制造正例。

## 5. 支持材料与完整失败历史

支持材料与主 SFT 候选分层保存，统一标记 `training_use=evidence_only_not_primary_sft` 和 `independent_sft_sample=false`。支持材料不能直接按文件数增加训练样本、任务数或技能数。

本轮只读处理旧包中 5,017 个来源：`sources/` 1,112 个、`source_materials/` 3,751 个、retained29 的 154 个文件。原始会话 corpus 与逐会话视图保留各自身份；重复视图不构成独立会话。输入 CAS 对象逐个校验哈希与大小，原索引前后哈希以及 154 个 retained 文件哈希保持不变。

最终支持清单有 **5,700 条**：5,017 个来源、682 个 ZIP 文件成员和 1 条历史依赖派生记录。其中提取 **4,750 条文字证据**，共 1,074,617,683 UTF-8 字节；文字 gzip 为 103,166,764 字节。该数量包含重复路径及派生成员。其余为排除 862 条、空文字 7 条、无法严格解码 81 条，均有清单原因，原件保留。

文字提取覆盖 DOCX 412 份、XLSX **177 份全部**、PPTX 61 份及 PDF 606 份；另 1 份 PPTX 和 2 份 PDF 无可提取文字。Office 使用 ZIP/XML 只读提取；Excel 记录单元格、公式和已存值，大表流式读取，未启动 Office、执行宏、重算公式或截断大表。PDF 仅提取现有文字层，不做 OCR。布局、图片及嵌入对象未被这一步恢复，不能把文字提取结果当成完整视觉验收。

旧包中的原生 canonical 历史有 **1,763 条会话记录**，连同 episode/job/route/source_material 目录、非 core7 收尾及其他失败过程，作为证据层保留。这里的完整保留指旧包已有记录不因候选筛选而消失，不声称早期所有 WRD 迭代已被百分之百恢复；未知或缺失历史仍是覆盖缺口。失败 target 不自动作为正例。

公开前区分以下情况：

- **无法安全提取的二进制或视觉内容：** 图片、媒体、旧二进制 Office、不可解码内容等保留本地原件与缺口清单，不直接当纯文本训练输入。
- **历史运行环境及无关资料：** 18,042 个归档运行环境文件保留成员类型和哈希清单，107 个包的历史依赖信息另存，并纳入统一文字清理入口。第三方库测试数据、ABI 相关二进制、密钥文件及 Git 内部资料不扩成 WRD 证据正例。旧环境不是 Spark ARM64 安装锁。
- **发布隐私 hold：** 是否包含凭据或第三方敏感个人信息，由统一隐私检查与公开/受控清单决定，和文件能否提取文字是两回事。文本也可能需 hold；有原件哈希也不表示允许公开原件。

本地工作输出最初全部标为未审核受控文字。公开文件需经过共同的 discover、冻结映射、统一去标识、复扫及 public/hold 分流。自动已知模式扫描不能证明未知敏感信息绝对不存在；无法确认的内容保持受控，并通过清单说明缺口。

文字提取成功不表示可以公开。公开层还对跨字段的个人资料表头及关联行做额外 gate：单独看某列可能不显敏感，组合后仍可能构成个人履历、认证或其他敏感资料。被 gate 的大表原文字留在本地工作层，公开侧只保留必要的 hold 元数据，不重复发布整表正文。该规则依赖已知表头与组合特征，对未知命名、转置、图片化或非标准个人资料结构仍可能识别不足，不能把通过 gate 当成隐私完全无风险的证明。

## 6. 防泄漏分组与训练 mask

旧包来源关系图只有 **1 个连通分量**，含 1,186 个关系节点，当前归入 train。不能随机切分相邻动作、同一来源的不同前缀或重复会话视图来得到“独立 dev/test”。目前没有可据此宣称的独立开发集或盲测集，需要另行获取与冻结新来源。

固定正式 226/250 评测及本轮在途 49 题消融不纳入新训练数据，不把其输出、评分或最新过程用于补标签或支持材料。本轮不读取新消融产物，不改变原题、技能、队列或成绩。来源排除清单需要保留；文件路径排除本身也不等于已证明全部来源在语义上绝无重叠。

SFT 编译只允许一条当前 assistant completion 作为监督目标。完整历史前缀、用户消息、工具结果和历史 assistant 均设为 ignore index `-100`；通过监督 span 可还原当前 completion 的 loss mask。编译检查 prompt/target token 边界、非空监督、终止 token、工具配对及双模型 token 与 mask 的一致性，不静默截断上下文。

16K/32K 共同覆盖率须由两套实际 tokenizer 对同一批完整样本编译得到，并分列全部候选、可公开和训练准入数量。能放入 16K/32K 的未审或拒绝样本仍不进入训练。超 32K 的完整记录继续保存于证据或候选层；不得为提高覆盖率随意裁掉历史。支持文字的 4,750 条不纳入主 SFT 长度覆盖率分母。

输入候选上的 `training_eligible` 是**编译前**标记。最终入口是 `FINAL_ADMISSION.json` 与 `admission.jsonl.gz`：先要求汇总 `status=PASS`、`release_ready=true`，再使用逐条 `final_admitted=true` 的 ID。16K 使用 `sft/common16k.jsonl.gz`；32K 使用它与 `sft/common32k_long_only.jsonl.gz` 的并集，两文件互斥。未通过边界、协议、mask 或长度校验的候选不能因为编译前标记为 true 就进入训练。

## 7. 复核入口与结论边界

来源核验见 `label_recovery_report.json`；结构检查见 `structure_report.json`；AI 一审、二审、收尾审核与 adjudication 分别保留逐条 ID、target 哈希、范围和理由；支持材料见 `support_extraction_report.json`、`support.manifest.jsonl.gz` 及 `archive_members.manifest.jsonl.gz`。公开包应附对应已清理版本及最终哈希回执，含原文的本地工作文件不因本说明公开而自动获准发布。

本轮产物证明数据来源、派生方式及审核覆盖可追溯，不构成小模型质量提升或算力节省的实证结果。14B 与 8B 的技能沉淀质量、每个合格技能总成本，以及训练与推理速度，仍需后续在获准启动的公平对照中测量；失败、修订、教师回退、验证和训练摊销成本都应保留。
